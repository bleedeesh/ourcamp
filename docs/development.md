# Разработка

## Что нужно установить (Windows)

1. **Rust** (stable, ≥ 1.80): <https://rustup.rs>. Установщик сам предложит
   «Visual Studio C++ Build Tools» — согласиться, нужен компонент «Desktop development with C++».
2. **Node.js ≥ 22.18** (в нём TypeScript запускается без сборки — так работают тесты).
3. **pnpm**: `corepack enable` (идёт с Node).
4. **WebView2** — уже есть в Windows 10/11.
5. **Docker Desktop** — для локального LiveKit (M2+), см. «Голос (M2)».

Проверка: `rustc --version`, `node --version`, `pnpm --version`.

Путь к проекту должен быть коротким (`C:\Users\<you>\Desktop\ourcamp` подходит): libwebrtc
распаковывается глубоко в `target`, а компилятор MSVC не открывает пути длиннее 260 символов.
Подробности — [ADR-0012](decisions/0012-windows-static-crt.md).

## Первый запуск

```powershell
cd C:\Users\<you>\Desktop\ourcamp
pnpm install
pnpm dev
```

Первая сборка Rust займёт несколько минут (Tauri и cpal компилируются один раз).
Откроется окно 380×720.

Первая сборка с M2 дольше: `webrtc-sys` один раз скачивает готовый libwebrtc (сотни МБ).

## Голос (M2): локальный LiveKit

По умолчанию клиент заходит в настоящую комнату LiveKit. Для разработки нужен
`livekit-server` в режиме `--dev` (ключ `devkey` / `secret`, токены клиент в debug-сборке
подписывает сам — [ADR-0010](decisions/0010-dev-room-tokens.md)).

1. Сервер — в Docker ([ADR-0013](decisions/0013-dev-livekit-in-docker.md)), ничего
   устанавливать не нужно. Запустить и оставить открытым (`pnpm livekit:down` — остановить):

   ```powershell
   pnpm livekit
   ```

2. Первый клиент, в другом терминале: `pnpm dev` (имя участника — `dima`).
3. Второй клиент на этой же машине, в третьем терминале (UI отдаёт тот же `pnpm dev`):

   ```powershell
   $env:OC_IDENTITY = "artem"; .\target\debug\ourcamp-desktop.exe
   ```

   С другого компьютера в той же сети: сервер запустить как
   `$env:OC_NODE_IP = "<IP этого ПК>"; pnpm livekit`, а у второго клиента задать
   `$env:OC_LIVEKIT_URL = "ws://<IP этого ПК>:7880"`. Windows может спросить разрешение
   брандмауэра для Docker — порты 7880–7881/tcp и 7882/udp.

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `OC_IDENTITY` | кто я в комнате (до аккаунтов, M4) | `dima` |
| `OC_LIVEKIT_URL` | адрес LiveKit | `ws://127.0.0.1:7880` |
| `OC_VOICE=synthetic` | вместо комнаты — синтетические голоса M0, без сервера и микрофона | — |

### Что проверить в M2

1. Оба клиента заходят в **«Лобби»**: в дереве костра у каждого — другой участник
   (демо-люди Артём/Лена/Макс из списка пропадают — состав теперь из комнаты).
2. Говорить в микрофон: у себя загорается своя рамка, у собеседника — твоя, и он тебя слышит.
3. Меню громкости собеседника 0–200 % работает так же, как в M0; громкость сохраняется.
4. Кнопка микрофона: у собеседника появляется значок выключенного микрофона, звук пропадает.
5. **Эхо**: с колонками (не наушниками) собеседник не должен слышать сам себя —
   работает AEC3 ([ADR-0009](decisions/0009-mic-processing-webrtc-apm.md)). Два клиента на
   одной машине с одним микрофоном слышат друг друга по-настоящему только в наушниках.
6. Выйти из костра и зайти снова — звук восстанавливается, микрофон Windows отпускается
   (значок микрофона в трее пропадает после выхода).

В консоли: `[oc-voice] microphone: <устройство> @ <частота> Hz`; ошибки подключения
показываются в окне.

### Что проверить в M0 (`OC_VOICE=synthetic`)

1. Кликнуть **«Лобби»** — зазвучат синтетические голоса Артёма и Лены (у каждого свой
   тон), у говорящего загорается рамка аватарки. Макс с выключенным микрофоном молчит.
2. Кликнуть (или правый клик) по **Лене** → меню громкости. Двигать ползунок 0–200 %:
   её голос должен становиться тише/громче **плавно, без щелчков**, остальные — не меняться.
3. «Заглушить для меня» — Лена замолкает, рамка при этом продолжает загораться
   (индикатор речи считается до громкости — так и задумано).
4. Поставить двоим 200 % — звук становится громче, но **не хрипит** (работает лимитер).
5. Кнопка **наушников** — тишина; повторно — всё вернулось с прежними громкостями.
6. Перезапустить приложение — громкости участников сохранились.

Если звука нет: в консоли `pnpm dev` будет строка `[oc-audio] output: <устройство> @ <частота> Hz`
или причина ошибки; она же показывается в окне.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm livekit` / `pnpm livekit:down` | локальный LiveKit в Docker: запустить / остановить |
| `pnpm dev` | клиент в режиме разработки (горячая перезагрузка UI) |
| `pnpm test` | тесты фронтенда (`node --test`) и Rust (`cargo test`) |
| `pnpm typecheck` | проверка типов TypeScript |
| `pnpm lint:rust` | clippy (pedantic, warnings = errors) + rustfmt |
| `pnpm --filter @ourcamp/desktop dev` | только UI в браузере, без звука (демо-движок) |
| `pnpm --filter @ourcamp/desktop tauri build` | установщик (`.msi`/`.exe`) |

## Иконки

`apps/desktop/app-icon.png` — исходник 1024×1024. Для macOS/Linux-пакетов:
`pnpm --filter @ourcamp/desktop tauri icon app-icon.png` сгенерирует все форматы.

## Соглашения

- Решения, которые не очевидны из кода, записываются в `docs/decisions/` (ADR).
- Rust: `cargo clippy` с pedantic-набором без предупреждений, `unsafe` только с
  комментарием `SAFETY:`.
- TypeScript: strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.
- Тесты рядом с кодом: `*.test.ts`, `#[cfg(test)] mod tests`.
