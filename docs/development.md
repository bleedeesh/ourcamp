# Разработка

## Что нужно установить (Windows)

1. **Rust** (stable, ≥ 1.89): <https://rustup.rs>. Установщик сам предложит
   «Visual Studio C++ Build Tools» — согласиться, нужен компонент «Desktop development with C++».
2. **Node.js ≥ 22.18** (в нём TypeScript запускается без сборки — так работают тесты).
3. **pnpm**: `corepack enable` (идёт с Node).
4. **WebView2** — уже есть в Windows 10/11.
5. **Docker Desktop** — для локального LiveKit (M2+), см. «Голос (M2)».

Проверка: `rustc --version`, `node --version`, `pnpm --version`.

Путь к проекту должен быть коротким (`C:\Users\<you>\Desktop\ourcamp` подходит): libwebrtc
распаковывается глубоко в `target`, а компилятор MSVC не открывает пути длиннее 260 символов.
Подробности — [ADR-0012](decisions/0012-windows-static-crt.md).

Linux: готовый libwebrtc требует **clang ≥ 21** (`CC=clang-21 CXX=clang++-21`), в Ubuntu 24.04
его ставят из <https://apt.llvm.org> — см. задачу `voice` в `.github/workflows/ci.yml`.

## Первый запуск

```powershell
cd C:\Users\<you>\Desktop\ourcamp
pnpm install
pnpm dev
```

Первая сборка Rust займёт несколько минут (Tauri и cpal компилируются один раз).
Откроется окно 380×720.

Первая сборка с M2 дольше: `webrtc-sys` один раз скачивает готовый libwebrtc (сотни МБ).

## Голос: лагерь, LiveKit и два клиента

Клиент заходит в лагерь по ссылке `ourcamp://`, а голос идёт через сервер лагеря
([ADR-0019](decisions/0019-voice-through-the-camp-port.md), [ADR-0020](decisions/0020-camps-in-the-app.md)).
Сервер лагеря сам запускает свой LiveKit ([ADR-0022](decisions/0022-managed-livekit.md)),
поэтому для разработки нужны два процесса, каждый в своём терминале:

1. Один раз — скачать livekit-server (закреплённая версия, проверка SHA-256, кладётся в
   `dev/bin`, ~20 МБ). На macOS готового бинарника нет: `brew install livekit`.

   ```powershell
   pnpm livekit:fetch
   ```

2. Сервер лагеря — поднимет LiveKit и напечатает ссылку для друзей (роли выдаются в окне
   сервера, ADR-0026):

   ```powershell
   pnpm server
   ```

3. Клиент: `pnpm dev` → «Войти по ссылке» → вставить ссылку для друзей → имя → «Войти в лагерь».

LiveKit в Docker ([ADR-0013](decisions/0013-dev-livekit-in-docker.md), `pnpm livekit`) остаётся
для тестов голоса приложения (`cargo test -p ourcamp-desktop -- --ignored --test-threads=1`: у тестов одна комната, ADR-0053) и для
`pnpm server:docker` (лагерь без своего LiveKit). Оба LiveKit берут порты 7881/7882 —
одновременно работает только один: `pnpm livekit:down` перед `pnpm server`.

Второй клиент на этой же машине — **другой профиль** (своя папка данных, свой ключ
устройства, то есть другой человек в лагере). UI отдаёт тот же `pnpm dev`:

```powershell
$env:OC_PROFILE = "artem"; .\target\debug\ourcamp-desktop.exe
```

То же в `cmd.exe` (кавычки обязательны, иначе в имя профиля попадёт пробел):

```bat
set "OC_PROFILE=artem"
target\debug\ourcamp-desktop.exe
```

В нём — «Войти по ссылке» и ссылка «для друзей» (или «Скопировать приглашение» в меню
лагеря у первого клиента).

С другого компьютера в той же сети ничего настраивать не нужно: сервер кладёт в ссылки IP
этого ПК в локальной сети и его же сообщает своему LiveKit для медиа (с Docker —
`$env:OC_NODE_IP = "<IP этого ПК>"; pnpm livekit`). Windows может спросить разрешение
брандмауэра: 7780/tcp (сервер лагеря), 7881/tcp и 7882/udp (голос).

| Переменная | Что делает | По умолчанию |
|---|---|---|
| `OC_PROFILE` | отдельный профиль (папка данных) — второй человек на этом ПК; только debug | — |
| `OC_VOICE=synthetic` | вместо комнаты — синтетические голоса M0, без сервера и микрофона | — |

Данные приложения (ключ устройства, список лагерей): `%APPDATA%\<id приложения>`, профили —
в `profiles\<имя>` внутри. Путь печатается при старте: `[ourcamp] data: …`.

### Что проверить в M3 (шаг 4a)

1. Первый запуск: «Пока ни одного лагеря» → «Войти по ссылке».
2. Вставить ссылку: под полем появляется карточка лагеря (название, число костров; для
   ключа админа — «вы станете админом»). Мусор вместо ссылки — понятная ошибка.
3. Войти: дерево костров — с сервера (Лобби, Катка, Отошёл). Перезапуск — лагерь открывается сам.
4. Меню лагеря → «Скопировать приглашение» → второй клиент входит по этой ссылке.
5. Оба в «Лобби» — слышат друг друга; громкость, микрофон, выход/вход — как в M2.
6. Выключить сервер лагеря и перезапустить клиент — лагерь открывается из кэша с
   предупреждением «сервер недоступен».

### Что проверить в M3 (шаг 4b)

1. Первый клиент сидит в «Лобби», второй **не заходит** в голос — и всё равно видит его там,
   с короной админа, в пределах секунды.
2. Первый выключает микрофон — у второго появляется значок; выходит из костра — исчезает.
3. Второе окно **без** `OC_PROFILE` не открывается: в консоли подсказка про профиль.
4. Остановить `pnpm server` — в шапке «нет связи с лагерем»; запустить снова — подпись
   исчезает, костры снова живые (переподключение само, без перезапуска клиента).

### Что проверить в M3 (шаг 5)

1. `pnpm livekit:down`, затем `pnpm server`: в логе `LiveKit (managed): pid …`, строки
   LiveKit идут с префиксом `[livekit]`. Клиенты слышат друг друга как раньше.
2. С запущенным `pnpm livekit` сервер не стартует и объясняет: порты 7881/7882 заняты.
3. Убить `livekit-server.exe` в диспетчере задач — в логе «LiveKit exited … restarting»,
   через секунду «LiveKit is back». Клиент в костре либо переподключится сам, либо покажет
   «Связь с костром потеряна — зайдите в него снова»; повторный вход в костёр работает.
4. Ctrl+C в терминале сервера — LiveKit останавливается вместе с ним (в диспетчере задач
   `livekit-server.exe` пропадает). То же, если закрыть окно терминала крестиком.

### Что проверить в M3 (шаг 6, окно сервера)

Окно — `pnpm server:window` (`pnpm livekit:down` и остановить `pnpm server` перед ним: тот же
порт 7780 и порты голоса). Его лагерь — **отдельный** от `target/camp-data`: папка данных
приложения, путь в консоли `[ourcamp-server] data: …`. Вёрстку без Tauri смотреть в браузере:
`pnpm --filter @ourcamp/server dev` (демо-данные).

1. Окно: название, «Лагерь работает», ссылка «для друзей»,
   «Скопировать» кладёт ссылку в буфер.
2. Войти клиентом по ссылке для друзей — в списке появляетесь вы (участник);
   сесть в костёр — справа его название, выключить микрофон — значок.
3. Крестик прячет окно, лагерь работает (клиент на связи); клик по значку в трее — окно
   снова; «Скопировать ссылку для друзей» в меню трея — ссылка в буфере. «Остановить лагерь
   и выйти» — процесс и `livekit-server.exe` пропадают. Повторный запуск окна показывает
   уже открытое.
4. Запустить окно, когда `pnpm server` уже работает, — понятная ошибка старта и
   «Попробовать снова» (остановить `pnpm server` и нажать — лагерь поднимается).
5. Закрыть клиент крестиком, сидя в костре, — в окне сервера человек пропадает из костра
   за секунду (клиент выходит из комнаты перед закрытием, а не ждёт таймаута LiveKit).

### Что проверить: роли и управление лагерем (ADR-0026)

Окно сервера — `pnpm server:window`; второй клиент — `OC_PROFILE`. Старый лагерь окна получит
миграцию v4: его костры останутся, ключ админа исчезнет, кто был админом — остался.

1. Новый лагерь (удалить папку данных окна): костры **Voice**, **AFK** и канал **Chat**; в
   клиенте видны только Voice и AFK (чаты — в M5). Ссылки «для вас» нет нигде.
2. Карандаш у названия лагеря → новое имя, Enter: у клиентов меняется шапка и переключатель
   лагерей сразу, без перезахода.
3. «Новый канал» → «Катка», Костёр → «Добавить»: у клиентов костёр появляется перед AFK.
   Переименовать его — имя меняется у всех.
4. Клиент сидит в «Катке» → удалить её в окне: у клиента «Костёр удалён», голос отключается,
   костёр пропадает из дерева. AFK удалить нельзя (кнопки нет).
5. Выбор роли у участника: «Модератор» — щит у него в окне и у всех в клиентах, «Админ» —
   корона; в меню лагеря у него самого «Вы модератор / Вы админ».
6. Старая ссылка `ourcamp://…/claim/…` в форме входа: «Ключ админа больше не действует».

### Что проверить: модерация (ADR-0028)

Окно сервера — `pnpm server:window`; два клиента (второй — `OC_PROFILE`), оба в Voice.
Лагерь окна получит миграцию v5 (флаг `silenced`).

1. Иконка микрофона у участника → «Запретить говорить»: у него микрофон гаснет сразу, его
   больше не слышно; кнопка микрофона заблокирована, под именем «Говорить запрещено»; у всех
   значок микрофона на красной подложке. Перезайти в канал или перезапустить клиент — запрет
   остаётся.
2. «Разрешить говорить» — его снова слышно без перезахода, кнопка снова работает.
3. Перетащить сидящего в голосе (в дереве каналов или в списке участников) на другой канал,
   например AFK: клиент сам переходит туда, тост «Вас перенесли в канал …». Бросить на его
   же канал, на Chat или мимо — ничего не происходит; Escape во время перетаскивания отменяет.
4. В клиенте: себя перетащить на другой канал — переход туда. Дать второму клиенту роль
   «Модератор» и перетащить им первого — тот переходит; модератора на админа перетащить
   нельзя (его не взять). Правый клик по участнику открывает его меню (громкость и модерация, ADR-0034).
5. «Выгнать» → подтвердить: клиент выходит из голоса, сервер пропадает из его списка, тост
   «Вас выгнали с сервера …». Зайти снова по ссылке для друзей — пускает.

### Что проверить: окно чата (ADR-0046)

Вёрстка без приложения: `desktop-ui` → `http://localhost:5173/chat.html` (демо, 420×660).

1. «Чат» в главном окне → окно чата справа от главного; повторный клик выводит его вперёд.
2. Крестик окна чата закрывает его (главное окно и голос остаются).
3. Второй клиент (`OC_PROFILE`) пишет → сообщение сразу в ленте; со свёрнутым окном чата —
   счётчик на «Чат» растёт; развернули окно у конца ленты — счётчик ушёл.
4. Фото: кнопка, Ctrl+V скриншота, перетаскивание файла; у второго клиента фото в ленте,
   клик — во всё окно.
5. Прокрутить вверх в длинном чате — подгружается без прыжков; «↓» возвращает к концу.
6. Сменить сервер в главном окне — окно чата показывает чаты нового.
7. Запретить писать (модератором) — вместо поля объяснение.

### Что проверить: стрим без окон (ADR-0049, шаг 1)

Интерфейса пока нет. С запущенным LiveKit (`pnpm livekit`) на настоящем экране:

```text
cargo test -p ourcamp-desktop --lib the_real_screen -- --ignored --nocapture
```

Печатает кодировщик и fps у зрителя. Ожидается аппаратный (`NVIDIA H.264 Encoder MFT` или аналог) и около 60 fps.

### Что проверить: удаление сообщений (ADR-0048)

1. Навести на своё сообщение → корзина → «Удалить для всех?» → сообщение пропало у обоих клиентов.
2. Обычный участник не видит корзину на чужих сообщениях; модератор видит на сообщениях участников.
3. Сообщение с фото: удалить — фото пропало и из ленты второго клиента.
4. Вставить много сообщений подряд скриптом или зажатым Enter: после десятка — «Слишком быстро», через пару секунд снова можно.

### Что проверить: сервер на Linux (ADR-0043)

Установку под systemd CI проверяет сам. Руками — на настоящем VPS:

1. Артефакт `ourcamp-server-linux-x64` из CI → на сервер, `tar xzf`, `sudo ./install.sh --host <IP>`.
2. `sudo ourcamp status` → ссылка; клиент заходит, голос идёт (порты TCP 7780, 7881, UDP 7882 открыты).
3. `sudo reboot` → сервер поднялся сам, ссылка та же.
4. Новый архив, `sudo ./install.sh` → настройки и люди на месте.

### Что проверить: домен с сертификатом (ADR-0042)

Нужен сервер с доменом и `certbot` (или любой сертификат от центра, которому доверяет ПК).

1. `oc-server --host ourcamp.kz --tls-cert /etc/letsencrypt/live/ourcamp.kz/fullchain.pem
   --tls-key /etc/letsencrypt/live/ourcamp.kz/privkey.pem` печатает `ourcamp://ourcamp.kz/join/…` без `fp`.
2. Клиент входит по этой ссылке; голос работает. Если раньше вы входили на тот же сервер по
   ссылке с `fp`, в списке будет два пункта (по имени и по отпечатку) — так задумано.
3. Ссылка с `fp` (старая) тоже работает.
4. С `cert.pem` вместо `fullchain.pem` сервер не стартует и говорит про fullchain.
5. `certbot renew --force-renewal` → через минуту в логе «certificate for … reloaded», клиенты не замечают.

### Что проверить: команды владельца (ADR-0041)

1. `pnpm server`, клиент заходит по ссылке. В другом терминале `pnpm server status`:
   название, ссылка, каналы, клиент в списке людей.
2. `pnpm server role <ник> moderator` → у клиента сразу меняется роль (значок в дереве).
3. `pnpm server channel add Тест` → канал появляется у клиента; `channel remove Тест` — пропадает.
4. `pnpm server silence <ник>` → клиент не может говорить; `unsilence` — снова может.
5. `pnpm server kick <ник>` → клиента выгоняет, как из окна.
6. Остановить сервер, `pnpm server status` → «сервер не запущен».

### Что проверить: открытый сервер (ADR-0040)

Вёрстка: `?demo=custom&open` в `server-ui`.

1. Окно сервера, «Вход» → «Открытый»: ссылка в карточке становится адресом без приглашения
   (`ourcamp://…?fp=…`).
2. Второй клиент (`OC_PROFILE`), «Войти по ссылке» с этим адресом: «Открытый сервер — приглашение не нужно»,
   вход без приглашения.
3. «По приглашению»: третий клиент с тем же адресом видит «пускает только по приглашению»; второй остаётся
   участником.
4. Headless: `cargo run -p oc-server -- --open` печатает «Открытый, для всех: ourcamp://…?fp=…».

### Что проверить: порты на роутере (ADR-0039)

Вёрстка: `?demo=router`, `router-noloop`, `router-failed`, `router-grey` в `server-ui`. Свой роутер только
на чтение: `cargo test -p oc-server --lib this_networks_router -- --ignored --nocapture` (найдёт роутер и его
внешний адрес, ничего не открывает).

1. Роутер с UPnP: в «Адресе в ссылке» есть «Интернет через роутер — внешний IP». «Серый» (100.64–100.127.x.x,
   192.168.x, 10.x) помечен «· серый»; выбрать — жёлтое предупреждение про CGNAT, порты не трогаются.
2. «Белый» адрес: выбрать «Интернет через роутер» — «Открываем порты…», затем «Порты открыты» (в
   веб-интерфейсе роутера появятся пробросы OurCamp 7780/7881 TCP, 7882 UDP). Друг из другой сети заходит по
   ссылке и говорит.
3. Закрыть окно сервера через трей «Остановить сервер и выйти» — пробросы на роутере исчезают.

### Что проверить: адрес для друзей (ADR-0037)

Вёрстку всех случаев без настоящих сетей смотреть в браузере (`server-ui`): `?demo=radmin` (по умолчанию),
`radmin-chosen`, `radmin-off`, `lan`, `all-vpns`, `custom`, `hosting` — см. `DEMO_ADDRESSES` в `src/api.ts`.

1. Окно сервера, карточка «Для друзей» → «Адрес в ссылке»: «Автоматически — 192.168.x», «Локальная сеть»,
   и Radmin VPN / Hamachi / Tailscale, если они включены. Под выбором — что нужно друзьям.
2. Включить Radmin VPN (сеть с другом), открыть список — появится «Radmin VPN — 26.x.x.x». Выбрать: сервер
   перезапустится, ссылка станет `ourcamp://26.x.x.x/…`. Друг из той же сети Radmin заходит по ней и
   говорит — без открытых портов.
3. Выключить Radmin и перезапустить окно: ссылка по основной сети и жёлтая надпись «Radmin VPN сейчас не
   найден». Включить снова, открыть список, выбрать — снова 26.x.
4. «Свой адрес» → `mycamp.duckdns.org` (или статичный IP) → «Применить»: ссылка с ним.
5. Headless: `cargo run -p oc-server -- --host radmin` — ссылка с 26.x; без Radmin — ошибка «is the VPN on?».

### Что проверить: аватарки (ADR-0035)

Окно сервера (база получит миграцию v6) и два клиента (второй — `OC_PROFILE`).

1. «Войти по ссылке»: над ником кружок «Аватарка» → выбрать картинку (любую: PNG, JPEG, GIF) —
   в кружке центральный квадрат. «Убрать» возвращает букву.
2. Войти с аватаркой: у второго клиента и в окне сервера (дерево каналов, список) вместо буквы картинка.
3. Перезапустить второй клиент с выключенным сервером: аватарка первого всё равно видна (кэш `avatars/`
   в папке данных).

### Что проверить: модерация из клиента (ADR-0033)

Окно сервера и два клиента (второй — `OC_PROFILE`), оба в голосе. Ролями управляет окно.

1. Клиент-участник: правый клик по другому — в меню только громкость, раздела модерации нет.
2. Дать первому «Модератор»: у второго (участника) в меню «Перенести в канал»,
   «Запретить говорить», «Выгнать с сервера».
   - «Запретить говорить» — его не слышно, у всех значок на красной подложке.
   - «Разрешить» — снова слышно.
   - «Перенести в канал» → канал — он переходит туда.
3. Дать второму тоже «Модератор»: у первого остаётся только перенос.
4. В окне сервера: правый клик по человеку (в дереве каналов или в списке) — меню «Перенести в канал»,
   «Запретить говорить», «Выгнать с сервера». Правый клик на пустом месте — ничего (меню браузера
   выключено), в поле «Новый канал» — обычное «Вставить» (ADR-0034).
5. Первому «Админ»: «Выгнать с сервера» → подтверждение → «Выгнан» у первого, а у второго
   «Вас выгнали с сервера …»; по ссылке он возвращается.

### Что проверить: пинг, трей, иконка (ADR-0030–0032)

1. Войти в канал: внизу сначала «Подключение…», через пару секунд полоски и «N ms»
   (с лагерем на этом же ПК — «<1 ms» или единицы ms). Наведение — оценка связи и канал.
2. Крестик клиента: окно прячется, голос продолжается (вас слышно). Значок в трее: клик —
   окно обратно; меню «Выйти из OurCamp» — выход из канала (в окне сервера вы пропадаете
   сразу) и закрытие.
3. Клиент спрятан → запустить OurCamp ещё раз: появляется то же окно, вторая копия не
   стартует. С `OC_PROFILE=lena` второй клиент запускается рядом, как раньше.
4. Окно сервера в панели задач, в трее, в своём заголовке и карточке статуса — костёр с фиолетовым
   значком «сервер», клиент — без. Старая картинка в панели задач после пересборки — кэш
   Проводника: `ie4uinit.exe -show`.

### Что проверить в M2

1. Оба клиента в **«Лобби»**: в дереве костра у каждого — другой участник.
2. Говорить в микрофон: у себя загорается своя рамка, у собеседника — твоя, и он тебя слышит.
3. Меню громкости собеседника 0–200 % работает так же, как в M0; громкость сохраняется.
4. Кнопка микрофона: у собеседника появляется значок выключенного микрофона, звук пропадает.
5. **Эхо**: с колонками (не наушниками) собеседник не должен слышать сам себя —
   работает AEC3 ([ADR-0009](decisions/0009-mic-processing-webrtc-apm.md)). Два клиента на
   одной машине с одним микрофоном слышат друг друга по-настоящему только в наушниках.
6. Выйти из костра и зайти снова — звук восстанавливается, микрофон Windows отпускается
   (значок микрофона в трее пропадает после выхода).

В консоли: `[oc-voice] microphone: <устройство> @ <частота> Hz`; ошибки показываются в окне.

### Что проверить в M0 (`OC_VOICE=synthetic`)

1. Кликнуть **«Лобби»** — зазвучат синтетические голоса Артёма и Лены (у каждого свой
   тон), у говорящего загорается рамка аватарки. Макс с выключенным микрофоном молчит.
2. Правый клик по **Лене** (или Enter на ней) → меню громкости. Двигать ползунок 0–200 %:
   её голос должен становиться тише/громче **плавно, без щелчков**, остальные — не меняться.
3. «Заглушить для меня» — Лена замолкает, рамка при этом продолжает загораться
   (индикатор речи считается до громкости — так и задумано).
4. Поставить двоим 200 % — звук становится громче, но **не хрипит** (работает лимитер).
5. Кнопка **наушников** — тишина; повторно — всё вернулось с прежними громкостями.
6. Перезапустить приложение — громкости участников сохранились.

Если звука нет: в консоли `pnpm dev` будет строка `[oc-audio] output: <устройство> @ <частота> Hz`
или причина ошибки; она же показывается в окне.

## Сервер для Linux (ADR-0043)

`pnpm server:pack` на Linux (после `pnpm livekit:fetch`; нужны `musl-tools` и
`rustup target add x86_64-unknown-linux-musl`) → `target/pack/ourcamp-server-<версия>-linux-x64.tar.gz`.
Обычно его собирает CI (задача `server-linux`, артефакты x64 и arm64). Как ставить —
`packaging/linux/README.txt` (он же в архиве).

## Сервер лагеря (M3)

Без окна: `pnpm server` (данные — в `target/camp-data`, LiveKit — свой, из `dev/bin`).
С окном — `pnpm server:window` (ниже, [ADR-0023](decisions/0023-server-window.md)).
При первом запуске создаются база, каналы, самоподписанный сертификат, ключ API для
LiveKit (`livekit-keys.json`), костры Voice, Chat и AFK, ссылка для друзей:

```text
[oc-server] fingerprint: _Sr2o8XYvU2szmjofpL8y3VsZdOgO-e0cqwXOJZqBP8
Для друзей: ourcamp://192.168.1.2/join/…?fp=…
```

Адрес в ссылках — IP компьютера в локальной сети (`--host` чтобы задать свой), порт 7780
по умолчанию не пишется. Все флаги: `cargo run -p oc-server -- --help`.
Удалить папку данных = новый лагерь с новым отпечатком: старые ссылки перестанут работать.

Управлять запущенным лагерем — командами владельца в другом терминале
([ADR-0041](decisions/0041-owner-cli.md)), тот же `--data`:

```text
pnpm server status
pnpm server role Лена admin
pnpm server channel add Чат команды --text
pnpm server kick Боб
```

## Команды

| Команда | Что делает |
|---|---|
| `pnpm livekit:fetch` | скачать закреплённый livekit-server в `dev/bin` (один раз) |
| `pnpm livekit` / `pnpm livekit:down` | локальный LiveKit в Docker: запустить / остановить |
| `pnpm server` | сервер лагеря без окна со своим LiveKit (данные в `target/camp-data`) |
| `pnpm server:docker` | то же, но с LiveKit из `pnpm livekit` |
| `pnpm server:window` | окно сервера лагеря (Tauri), лагерь в папке данных приложения |
| `pnpm dev` | клиент в режиме разработки (горячая перезагрузка UI) |
| `pnpm test` | тесты фронтенда (`node --test`) и Rust (`cargo test`) |
| `pnpm typecheck` | проверка типов TypeScript |
| `pnpm lint:rust` | clippy (pedantic, warnings = errors) + rustfmt |
| `pnpm --filter @ourcamp/desktop dev` | только UI в браузере, без звука (демо-движок) |
| `pnpm --filter @ourcamp/desktop tauri build` | установщик (`.msi`/`.exe`) |

## Иконки

`apps/desktop/app-icon.svg` — исходник иконки клиента (палитра «Ночь», ADR-0024), `apps/server/app-icon.svg` —
окна сервера (костёр со значком «сервер», ADR-0032). `pnpm tauri icon app-icon.svg -o <папка>` в папке
приложения строит все форматы; в `src-tauri/icons` кладём пять файлов из `tauri.conf.json` и `icon.png`.

## Соглашения

- Решения, которые не очевидны из кода, записываются в `docs/decisions/` (ADR).
- Rust: `cargo clippy` с pedantic-набором без предупреждений, `unsafe` только с
  комментарием `SAFETY:`.
- TypeScript: strict + `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`.
- Тесты рядом с кодом: `*.test.ts`, `#[cfg(test)] mod tests`.
