## Что восстановить на новом компьютере

Что поставить — в [development.md](development.md). На паузе стояли rustc 1.99.1 и Node 24.21.0.

```bash
git clone https://github.com/bleedeesh/ourcamp.git
cd ourcamp
pnpm install
pnpm livekit:fetch
sh dev/check/all.sh
```

- Путь к проекту должен быть коротким (ADR-0012). `target` разрастается: `target/debug/incremental` доходил до ~100 ГБ.
- Первая сборка скачивает libwebrtc. Снаружи проект зависит от релизов LiveKit (бинарник с проверкой SHA-256),
  от готового libwebrtc для `webrtc-sys` и от git-тега `deep_filter`. Если что-то из этого исчезло, начинать с этого.
- Новый Rust может принести новые замечания clippy pedantic, а новый SDK LiveKit, возможно, позволит убрать
  `vendor/livekit-0.9.7` (что там правлено — в `CLAUDE.md`).
- `.claude/launch.json` в git не лежит, потому что в нём пути машины. Для приложения Claude:

```json
{
  "version": "0.0.1",
  "configurations": [
    {
      "name": "desktop-ui",
      "runtimeExecutable": "node",
      "runtimeArgs": ["node_modules/vite/bin/vite.js", "--port", "5173", "--strictPort"],
      "cwd": "apps/desktop",
      "port": 5173
    },
    {
      "name": "server-ui",
      "runtimeExecutable": "node",
      "runtimeArgs": ["node_modules/vite/bin/vite.js", "--port", "5175", "--strictPort"],
      "cwd": "apps/server",
      "port": 5175
    }
  ]
}
```

## Что живёт не в репозитории

| Что | Где | Что будет, если потерять |
|---|---|---|
| Ключ устройства и список серверов клиента | `%APPDATA%\app.ourcamp.desktop` (`device.key`, `camps.json`) | на серверах вы станете новым человеком, роль придётся выдавать заново |
| Сервер, запущенный из окна | `%APPDATA%\app.ourcamp.server` (`camp.db`, `tls`, `livekit-keys.json`) | новый сервер с новым отпечатком: старые ссылки, люди, роли и чаты пропадут |
| Макеты | [артефакт в аккаунте claude.ai](https://claude.ai/artifact/A9mZCWav7VeKur4eVfdwgA), копии в репозитории нет | не зависит от компьютера, живёт, пока жив аккаунт |
| История работы с Claude | `~/.claude/projects` на этом ПК | контекст решений есть в ADR, переписка пропадёт |

**Эти папки не класть в репозиторий:** он публичный, а там приватные ключи. Удаление папки проекта их не затрагивает,
они остаются в `%APPDATA%`.

## Как проверять

- `sh dev/check/all.sh` — всё перед PR.
- `sh dev/check/app.sh dev/check/open-link.mjs` — сценарий в настоящем приложении. По его образцу и `cdp.mjs`
  пишутся другие: окна, команды и события через демо в браузере не проверить (ADR-0047).
- Два клиента на одном ПК: оба с `OC_PROFILE` и одним `--remote-debugging-port`, запускать с паузой ~4 с. Порядок страниц на
  порту может поменяться.
- Сборка с `tauri build --debug --no-bundle` отдаёт встроенные страницы и понимает `OC_PROFILE` (ADR-0074).

## Известные проблемы

- `a_stream_gets_its_bitrate_at_once` падает сериями, причина не найдена (ADR-0067). Перезапускать, не чинить вслепую.
  Из-за него `all.sh` может сказать `SOMETHING FAILED`: на паузе он упал в одном прогоне из пяти. Смотреть, какой тест упал.
- Тесты на `windows-latest` иногда падали нативно (`STATUS_ACCESS_VIOLATION`), а стека в CI не видно. Задача, не начата:
  - в `.github/workflows/ci.yml` включить на раннере дампы Windows Error Reporting (`LocalDumps`);
  - при неудаче разобрать их через `cdb -z` (`.lastevent; .ecxr; r; kn 60; ~*kn 25`) и вывести стеки в лог;
  - дампы и `.pdb` выложить артефактом с коротким сроком;
  - код выхода тестов сохранить, успешный прогон не замедлять.
- Микрофоны не на 48 кГц остаются с шумодавом WebRTC, нужен ресемплинг (ADR-0073).
- Стримы только на Windows (ADR-0056).
- Карточки ссылок: `giphy.com/gifs/…` без карточки, Habr отвечает 403, Reddit отдаёт только заголовок. Приложение представляется
  своим именем и под чужих ботов не подделывается (ADR-0077).
- `docs/sedThTqem` — пустой мусорный файл из первого коммита, можно удалить.

## Нагрузка и хостинг

Сервер — SFU: он копирует каждый поток каждому получателю. Узкое место — исходящий канал, а не CPU.

- **Стрим:** уходит только тем, кто открыл просмотр (`auto_subscribe=false`). Стрим N Мбит/с на K зрителей — это N×K Мбит/с.
- **Голос:** микрофоны идут без DTX, поэтому канал на 10 человек — около 90 потоков, ~7 Мбит/с (считал по 80 кбит/с).
- **Чего нет:** лимитов LiveKit, ограничения числа стримов и показателя нагрузки в окне сервера. При перегрузке страдают все.
  Если захочется: потолок исходящего, лимит стримов, индикатор. Нагрузочный тест не делался.
- **Начать проще всего** с домашнего ПК с белым IP.

Просмотрено 2026-11-02, цены устаревают. Ни один хостинг не проверен вживую, курс ~520 ₸/$ примерный.

## Правила для агента

Дополняют `CLAUDE.md`. Выросли из работы и действуют дальше.

- Коммит, пуш и PR — только по просьбе Димы, с веткой от `main`. Auto-merge не включать. Тег — только после предупреждения.
- Системные настройки не менять: политику PowerShell, звуковое устройство по умолчанию.
- Не открывать порты на роутере и не запускать `--host router` без явного разрешения. Проверки UPnP — только на чтение.
- Не завершать `ourcamp-desktop` и `livekit-server` по имени образа, только свои процессы по PID.
- Профиль `artem` — Димин. Перед сборками Rust и нагрузкой проверять, что не идут `pnpm dev` или игры.
- Токен GitHub из диспетчера учётных данных не доставать, пароли в браузер не вводить.
- Заголовки окон и содержимое кадров из проб не печатать. Микрофон читать только числами уровня, не записывать.
- Не притворяться чужими ботами в User-Agent.
- В релизных и CI-утверждениях говорить только о проверенном: что не запускалось, то «не проверено».
