# Архитектура

```
                    ┌─────────────────────────────┐
                    │  Accounts service (общий)   │  вход, друзья, личные сообщения,
                    │  Node + TS · PostgreSQL     │  статусы, список лагерей пользователя
                    └──────────────┬──────────────┘
                                   │ HTTPS + WebSocket
┌──────────────────────────────────┼───────────────────────────────────────────┐
│ OurCamp (клиент, у каждого)      │                                           │
│                                  ▼                                           │
│  ┌───────────── webview (React) ──────────────┐   окна: главное, чат,        │
│  │ UI · стор · VoiceController                │   стрим, настройки           │
│  └───────────────┬────────────────────────────┘                              │
│                  │ Tauri IPC (команды + события, без аудио)                  │
│  ┌───────────────▼──────────── Rust ──────────────────────────────────────┐  │
│  │ Engine ── oc-audio mixer ── cpal (устройство вывода)                    │  │
│  │    └── (M2) LiveKit Rust SDK / libwebrtc: Opus, AEC3, шумодав, захват  │  │
│  └────────────────────────────────┬────────────────────────────────────────┘  │
└───────────────────────────────────┼──────────────────────────────────────────┘
                                    │ WebRTC (UDP) + TLS с пиннингом сертификата
                    ┌───────────────▼─────────────┐
                    │ OurCamp Server (у хозяина)  │  API лагеря, SQLite, LiveKit (SFU),
                    │ Rust · один установщик      │  ключ админа, приглашения, UPnP
                    └─────────────────────────────┘
```

## Принципы

1. **Звук не проходит через webview.** Захват, кодирование, микширование и вывод —
   в Rust. UI только командует и получает уровни для подсветки (≈20 раз/с).
   → [ADR-0002](decisions/0002-native-media-engine.md)
2. **Лагерь живёт у пользователя.** Голос и чаты лагеря хранятся и маршрутизируются
   на компьютере хозяина; общий сервис знает только аккаунты и друзей.
   → [ADR-0003](decisions/0003-self-hosted-camps.md)
3. **Аудиопоток реального времени не блокируется и не аллоцирует.**
   → [ADR-0006](decisions/0006-own-audio-mixer.md)
4. **Одна точка правды для каждого состояния.** Громкости — у слушателя
   (`VolumeBook`), живые уровни — в микшере, участники канала — на сервере лагеря.

## Поток звука собеседника (с M2)

```
сеть → libwebrtc (NetEq: джиттер-буфер, Opus-декодер, FEC/RED)
     → SourceInput (lock-free кольцо, ≤500 мс, задержка ограничена 120 мс)
     → MixerCore: уровень и детектор речи → громкость участника (плавно) → сумма
     → общая громкость / «выключить звук» → лимитер −1 dBFS → cpal → наушники
```

## Клиент: слои

| Слой | Где | Ответственность |
|---|---|---|
| UI | `apps/desktop/src/ui` | только отрисовка и события пользователя |
| Домен | `apps/desktop/src/domain` | `VoiceController`: состояние, оптимистичные обновления с откатом |
| Движок (граница) | `apps/desktop/src/engine` | интерфейс `VoiceEngine`; `TauriEngine` (Rust) и `DemoEngine` (браузер) |
| Нативный | `apps/desktop/src-tauri` | команды Tauri, `Engine`, устройство, события уровней |
| Ядро | `crates/oc-audio` | микшер, не знает ни про Tauri, ни про сеть |
