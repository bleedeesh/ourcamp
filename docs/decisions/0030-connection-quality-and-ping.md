# 0030. Качество связи и пинг в панели

**Дата:** 2026-10-28 · **Статус:** принято · **Код:** `apps/desktop/src-tauri/src/voice/room.rs`
(`watch_link`, `rtt_ms`), `participants.rs` (`voice://link`), `src/domain/link.ts`,
`src/ui/BottomPanel.tsx`

## Контекст
Строка над своим именем писала «В канале Лобби». Это и так видно по подсвеченному каналу в
дереве. Человеку важнее, как его слышно: какая связь и какой пинг.

## Решение
- Строка показывает **полоски сигнала и пинг**: «10 ms». Оценка связи — цветом и числом
  полосок, словами — в подсказке вместе с названием канала. Слова «Отличная связь» в
  строке Дима счёл лишними.
- **Серые полоски** — пока пинг не измерен («Подключение…») и пока сервер недоступен (нет
  потока событий лагеря): цветная оценка LiveKit без замера или без сервера ничего не
  обещает.
- **Оценка** — `connection_quality()` LiveKit (отличная / хорошая / слабая / потеряна). Её
  считает сервер по потерям, джиттеру и задержке, ту же оценку показывают его клиенты.
- **Пинг** — `currentRoundTripTime` выбранной ICE-пары из `get_stats()`: время до
  голосового сервера по тому же пути, по которому идёт звук. STUN-проверки обновляют его
  даже в тишине. Сначала берётся транспорт приёма (он есть всегда), потом отправки (у того,
  кому запретили говорить, отправки может не быть). Меньше 1 мс — «<1 ms» (сервер в сети).
- Комната замеряет раз в 2 с и сообщает движку **только изменения**
  (`RoomHost::link_changed`). Движок передаёт в UI только отчёты текущей комнаты,
  событие — `voice://link`. При входе в другой канал строка сбрасывается на «Подключение…»,
  пока новая комната не замерит связь.
- Контракт UI↔движок расширен методом `onLink`. Без него пинг до UI не довести.

## Отвергнуто
- **Пинг HTTP-запросом к лагерю** — меряет не путь звука (TLS-порт, а не UDP LiveKit) и
  добавляет трафик.
- **Пинг по сигнальному WebSocket** — то же: это не путь звука.
- **Показывать пинг и вне канала** — без комнаты мерить нечего, а «сервер доступен» уже
  видно по состоянию лагеря.
