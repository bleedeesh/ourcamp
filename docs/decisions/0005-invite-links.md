# 0005. Ссылки `ourcamp://` и одноразовый ключ админа

**Дата:** 2026-10-27 · **Статус:** принято · **Код:** `crates/oc-invite`

## Контекст
Друзья заходят в лагерь по ссылке. У сервера нет домена и сертификата от УЦ. Первым
делом хозяин должен стать админом, и никто другой не должен успеть это сделать.

## Решение
```
ourcamp://<host>[:port]/join/<16 символов>?fp=<43 символа>    приглашение
ourcamp://<host>[:port]/claim/<26 символов>?fp=<43 символа>   ключ админа (одноразовый)
```
- **fp** — SHA-256 сертификата сервера (base64url). Клиент принимает соединение только
  с этим сертификатом: ссылку нельзя подменить, даже без УЦ.
- **Ключ админа** сервер показывает в своём окне при первом запуске, отдельно от
  приглашения. Срабатывает один раз.
- Токены — случайные байты (80/128 бит) в Crockford base32: без похожих символов,
  можно продиктовать; `O→0`, `I/L→1` при вводе.
- Порт 7780 по умолчанию не пишется.

## Отвергнуто
- **«Админ — первый вошедший»** (первоначальная идея): если хозяин отправит ссылку
  раньше, чем зайдёт сам, админом станет другой.
- **Обычный https + Let's Encrypt** — нужен домен у каждого хозяина.

## Последствия
- При смене IP хозяина ссылка устаревает → в M3 предусмотреть обновляемую ссылку
  (через accounts-сервис по id лагеря).
