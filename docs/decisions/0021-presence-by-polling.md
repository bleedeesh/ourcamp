# 0021. Присутствие: сервер опрашивает LiveKit и рассылает снимки лагеря

**Дата:** 2026-10-28 · **Статус:** принято · заменяет часть [0004](0004-livekit-sfu.md) про вебхуки ·
**Код:** `crates/oc-server/src/presence.rs`, `crates/oc-camp-client/src/events.rs`,
`apps/desktop/src-tauri/src/camps.rs` (`follow`), `apps/desktop/src/domain/roster.ts` (`applyCampState`)

## Контекст
Клиент видел людей только в своём костре — из комнаты LiveKit, в которую он вошёл.
Дерево должно показывать всех во всех кострах, с короной админа, без входа в голос.

## Решение
- **Сервер раз в секунду опрашивает LiveKit по loopback** (Twirp `RoomService`:
  `ListRooms`, затем `ListParticipants` на комнату), собирает снимок `CampState`:
  участники лагеря из базы (имя, админ) + кто в каком костре (микрофон вкл/выкл), только
  каналы и участники этого лагеря. Публикует **только при изменении** (`watch` +
  `send_if_modified`).
- **Клиентам — WebSocket `GET /api/v1/events`** на порту лагеря, с сессией в заголовке
  (проверяется до апгрейда: чужой получает 401). Сообщения — JSON с тегом `type`;
  пока одно, `state` — **полный снимок** (пропуск не рассинхронизирует). Пинг раз в 30 с.
- **Клиент** держит поток для открытого лагеря: переподключение с паузой 1→15 с,
  повторный вход при истёкшей сессии, `online: false` в UI («нет связи с лагерем»).
- **Слияние в UI**: профили и все костры — из снимка; **свой костёр — из комнаты**
  (быстрее и точнее, чем опрос раз в секунду); себя присутствие не перечисляет.

## Детали LiveKit, проверенные на `livekit-server` 1.13
- JSON ответов — в `snake_case` (`creation_time`, `empty_timeout`).
- `ListParticipants` требует админский токен **с названием комнаты** (`roomAdmin` +
  `room`), иначе 401 — токен подписывается на каждую комнату (HMAC, дёшево).
- Микрофон: `tracks[]` с `type: "AUDIO"`, `source: "MICROPHONE"`, `muted`.

## Почему опрос, а не вебхуки (ADR-0004)
- Вебхуки LiveKit шлёт на HTTPS, проверяя сертификат по УЦ, — самоподписанный сервер
  лагеря он не примет; отдельный HTTP-порт для вебхуков — лишняя поверхность.
- В разработке LiveKit в Docker: достучаться до хоста — `host.docker.internal`, ещё
  одна настройка.
- Масштаб лагеря — единицы комнат и десятки людей: секундный опрос локального API
  ничего не стоит, а задержка в секунду для дерева незаметна (в своём костре её нет).

## Последствия
- LiveKit недоступен → костры пустые, участники лагеря всё равно приходят; сервер пишет
  в лог один раз на сбой.
- Новые события (чат M5, стримы M6) добавляются вариантами `CampEvent` без новой ручки.
- В M3 шаг 5 (LiveKit `managed`) опрос не меняется — тот же loopback.
