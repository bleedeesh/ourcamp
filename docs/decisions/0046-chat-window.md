# 0046. Окно чата: отдельная страница, лента без дыр

**Дата:** 2026-10-29 · **Статус:** принято · M5 шаг 3, дополняет [0044](0044-chats.md), [0045](0045-chat-read-marks.md) ·
**Код:** `apps/desktop/chat.html`, `src/chat-main.tsx`, `src/domain/chat-window.ts`, `src/domain/chat-feed.ts`,
`src/ui/chat/`, `src-tauri/src/windows.rs`

## Контекст
По макету (экран 9) чат — отдельное окно рядом с главным: вкладки, лента, поле ввода.
Главное окно маленькое (380×720) и занято голосом.

## Решение
- **Отдельное окно Tauri `chat`.**
  - Открывается кнопкой «Чат», а если уже открыто — выходит вперёд.
  - Размер 420×660, ставится справа от главного, если на экране есть место.
  - Своя рамка, как у главного окна.
  - Крестик закрывает его по-настоящему: в трей прячется только главное окно ([ADR-0031](0031-client-tray.md)).
  - Права (`capabilities`) те же, что у главного.
- **Отдельная страница того же фронтенда** (`chat.html`, сборка Vite из двух страниц).
  Своё дерево React и свой `ChatController`: окну не нужны ни голос, ни список серверов,
  а сбой одного окна не роняет другое.
- **Какой сервер показывать.**
  - Тот, что открыт в главном окне. Окно чата получает его командой `chat_context`:
    сервер, как его открыли, плюс последний снимок. Rust хранит последний `CampLive`.
  - Сменился сервер в главном окне — `camp://state` придёт с другим `campId`, и чат
    загрузится заново.
  - Сервер не открыт — окно так и пишет.
- **Лента без дыр** (`ChatController`):
  - Чат открывается последней страницей (50). Прокрутка вверх подгружает страницы
    назад, место на экране не прыгает.
  - Новое сообщение со следующим номером добавляется сразу.
  - Если номер дальше следующего (событие потерялось, связь пропадала), окно дочитывает
    пропущенное историей. То же после снимка, где у чата номер больше, чем в ленте.
  - Если отстали больше чем на страницу, последняя страница встаёт отдельно, а старое
    подгрузится прокруткой.
- **Прочитано, когда видно:** окно в фокусе, вкладка видима, лента у конца. Тогда чат
  отмечается прочитанным (ADR-0045), и счётчик в главном окне обновляется сразу.
- **Вид по макету.**
  - Дни («Сегодня», «Вчера», «12 октября»).
  - Подряд идущие сообщения одного автора (меньше 5 минут между ними) — без повторной
    шапки, время показывается при наведении.
  - Черта «Новые сообщения» перед первым непрочитанным чужим.
  - Кнопка «к новым», когда ты прокрутил вверх.
  - Ушедший автор показан с тем именем, с которым писал.
- **Поле ввода.**
  - Enter отправляет, Shift+Enter переносит строку; во время набора через метод ввода
    Enter не отправляет.
  - Поле растёт до ~6 строк.
  - Счётчик появляется с 1800 символов.
  - Если отправка не прошла, черновик и фото остаются с причиной.
  - Запрет говорить или недоступный сервер — вместо поля объяснение.
- **Фото.**
  - Кнопка, вставка из буфера или перетаскивание на окно.
  - Уменьшается до 1600 px по длинной стороне и перекодируется в WebP, если веб-вью не
    умеет — в JPEG. Средствами веб-вью, без библиотек.
  - Перекодирование заодно не пускает на сервер метаданные камеры, включая геолокацию.
  - В ленте место под фото заранее занято по его размерам, поэтому лента не прыгает.
  - По клику — просмотр во всё окно, Esc закрывает.
- **Аватарки в обоих окнах** берутся из `AvatarSourceContext`: компонент `Avatar` общий.
- **Демо в браузере:** `chat.html` со своими чатами из макета. Через 3 с приходит новое
  сообщение; отправленные фото хранятся до перезагрузки страницы.

## Отвергнуто
- **Чат внутри главного окна** — по макету и CLAUDE.md чат, стрим и настройки — отдельные
  окна; в 380 px ленте негде жить.
- **Одна страница с `?window=chat`** — в окне чата грузился бы весь код голоса и дерева.
- **Окно через `window.open` из главного** — Tauri открывает такие окна как веб-попапы, без
  своей рамки и прав. `WebviewWindowBuilder` в Rust даёт обычное окно приложения.
- **Ссылки в сообщениях кликабельными** — открывать их надо через системный браузер
  (плагин `opener`), с подтверждением. Отдельной записью, когда понадобится.

## Последствия
- `useBytesUrl` (превью аватарки при входе) переписан: URL создаётся и отзывается в одном
  эффекте. Двойной запуск эффектов в режиме разработки React раньше оставлял на картинке
  уже отозванную ссылку.
