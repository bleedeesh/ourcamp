# 0042. Домен с настоящим сертификатом: ссылка без отпечатка

**Дата:** 2026-10-29 · **Статус:** принято · выполняет часть [0036](0036-server-address-and-links.md) ·
дополняет [0014](0014-pinned-signalling-transport.md), [0018](0018-camp-login-protocol.md) ·
**Код:** `crates/oc-tls` (`Trust`), `crates/oc-server/src/certificate.rs`, `crates/oc-invite`,
`crates/oc-proto` (`CampKey`), `crates/oc-camp-client`, `apps/desktop/src-tauri/src/camps.rs`

## Контекст
Сервер на хостинге с доменом может получить сертификат от удостоверяющего центра
(Let's Encrypt, `certbot`). Тогда отпечаток в ссылке не нужен: клиент проверяет сертификат
по имени домена, как браузер. Ссылка становится `ourcamp://ourcamp.kz` или
`ourcamp://ourcamp.kz/join/…`. Её можно продиктовать, и она переживает продление
сертификата.

## Решение
- **Ссылка.** `fp` необязателен для домена; для IP-адреса — обязателен
  (`InviteError::MissingFingerprint`). Ни один центр не подтвердит адрес домашнего ПК, а
  ссылка на IP без отпечатка — почти наверняка обрезанная. В `Invite`/`Address`
  поле `fingerprint` стало `Option`.
- **Клиент: `oc_tls::Trust`.**
  - `Pin(fp)` — как раньше.
  - `Authorities(roots)` — проверка цепочки до корня из хранилища компьютера
    (`rustls-native-certs`, уже был в дереве через LiveKit SDK): имя, сроки, подписи.
    Корни читаются один раз.
  - `Trust::of(link.fingerprint())` выбирает режим. Тот же `Trust` идёт в HTTP, в поток
    событий и в транспорт LiveKit (`transport::trust`), поэтому голос защищён так же.
  - Клиент с отпечатком называет сервер `ourcamp` (SNI), клиент без него — именем домена.
- **Сервер: `--tls-cert fullchain.pem --tls-key privkey.pem` вместе с `--host ДОМЕН`.**
  - Свой самоподписанный сертификат остаётся. `Resolver` выбирает сертификат по SNI: на
    имя домена — от центра, на всё остальное — свой. Старые ссылки с `fp` продолжают
    работать, ссылки в логе и в `status` — уже без него.
  - **Проверка при старте.**
    - Ключ подходит к сертификату.
    - Сертификат выдан на этот домен, срок не истёк.
    - В файле есть промежуточный сертификат: одиночный — это `cert.pem` вместо
      `fullchain.pem` или самоподписанный.

    Цепочка проверяется до последнего сертификата в файле. Корня на сервере может не быть,
    а доверие центру всё равно решают клиенты. С ошибкой в файлах сервер не стартует и
    пишет, что именно не так.
  - **Продление.** Раз в минуту сервер смотрит время изменения файлов. Если они поменялись
    (и оба на месте), перечитывает их без перезапуска. Если новые файлы битые, старый сертификат
    остаётся в работе, а причина пишется в лог.
- **Подпись входа (ADR-0018) привязана к тому, что проверил клиент**
  (`oc_proto::CampKey`):
  - отпечаток — как раньше;
  - `name:домен:порт` — для сертификата от центра.

  Сервер принимает свой отпечаток всегда, а имя — только если у него есть сертификат на
  этот домен. Подпись, собранную `evil.kz`, нельзя предъявить `ourcamp.kz`, а подпись для
  одного порта — другому лагерю на том же домене. Формат старых подписей не изменился.
- **Сервер на домене в списке клиента** запоминается как `домен:порт`
  (`SavedCamp.by_name`). Отпечаток меняется при каждом продлении, поэтому не годится как
  id. Старые `camps.json` читаются как раньше.
- **Ошибки сертификата у клиента различаются по типу** (`ClientError::certificate_problem`):
  «не совпадает со ссылкой», «истёк срок», «выдан для другого адреса», «не подтверждён
  центром». Раньше выбирали по тексту ошибки.

## Отвергнуто
- **Получать сертификат прямо в сервере (ACME, `tls-alpn-01` на 7780).** На хостинге
  `certbot` обычно уже стоит, а свой ACME-клиент (JWS, аккаунт, заказы, продление) — это
  большой кусок кода. Отдельной записью — когда станет нужно серверам без `certbot`.
- **Вшить корни Mozilla (`webpki-roots`).** Хранилище системы обновляет ОС и учитывает
  корни, добавленные на компьютере.
- **Считать id сервера по отпечатку из ответа `/api/v1/camp`.** Чужой сервер мог бы назвать
  чужой id и подменить запись в списке.
- **Отдавать сертификат центра всем клиентам.** Старые ссылки с `fp` сломались бы при
  первом продлении.
- **Сертификат в окне сервера.** Окно — для домашнего ПК, где домена с сертификатом
  обычно нет. Пока только headless.

## Последствия
- Если у домена есть AAAA-запись, а сервер слушает только IPv4 (`0.0.0.0`), Windows-клиент
  тратит около 2 с на отказ по IPv6, прежде чем попробовать IPv4. Владельцу домена
  без IPv6 на сервере AAAA-запись не нужна. Слушать оба протокола — отдельная задача.
