# 0025. Системный костёр AFK

**Дата:** 2026-10-28 · **Статус:** принято ·
**Код:** `crates/oc-server/src/store.rs` (миграция v3, `ENSURE_AFK`), `oc_proto::Channel::afk`,
`apps/desktop/src/domain/voice.ts` (`#beforeAfk`)

## Контекст
Нужен костёр «отошёл»: человек виден в лагере, но не слышит и не говорит. У лагерей уже
был третий костёр по умолчанию «Отошёл (AFK)» — без всякого особого поведения.

## Решение
- **Флаг `afk` у канала** (`channels.afk`, `oc_proto::Channel::afk`; в старых ответах и в
  кэше клиента его нет — `false`). В лагере ровно один такой костёр; удалить его будет
  нельзя (управление каналами — следующий блок).
- **Миграция v3:** «Отошёл (AFK)» (`c2`) становится «AFK» с флагом — тот же id, то есть
  та же комната LiveKit; лагерь без него получает новый `afk` в конце.
- **Поведение — в клиенте.** Вход в AFK: клиент запоминает микрофон и звук и выключает оба
  **до** подключения комнаты (ничего не просочится ни туда, ни обратно). Выход — любым
  путём: другой костёр, «выйти», смена лагеря, разрыв связи — возвращает как было. Внутри
  можно включить звук вручную; микрофон при этом остаётся выключенным.
- В дереве у AFK — луна вместо костра и подсказка.

## Почему не на сервере
Токен комнаты для AFK мог бы запрещать публикацию и подписку (`canPublish`/`canSubscribe =
false`) — это защищает от изменённого клиента, но тогда движку нужен режим «войти без
микрофона», а пользы для друзей, сидящих у костра, — никакой: AFK — про удобство, не про
доступ. Если появится нужда (модерация, M4+), запрет в токене добавляется без смены UI.
