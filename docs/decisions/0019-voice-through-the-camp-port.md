# 0019. Голос через порт лагеря: прокси `/rtc` и закреплённый транспорт LiveKit

**Дата:** 2026-10-27 · **Статус:** принято · реализует [0014](0014-pinned-signalling-transport.md),
уточняет [0018](0018-camp-login-protocol.md) · **Код:** `crates/oc-server/src/rtc.rs`,
`crates/oc-camp-client/src/transport.rs`

## Решение
- **Сервер** проксирует `/rtc` и всё под ним (`/rtc/v1`, `…/validate`) в LiveKit по
  `ws://` на loopback: обычные запросы как есть, WebSocket — через `101` с обеих сторон и
  копирование байтов между «апгрейднутыми» соединениями. `Host` переписывается на адрес
  LiveKit, hop-by-hop заголовки не пересылаются. **Остальной HTTP API LiveKit**
  (`/twirp/…`, управление комнатами) наружу не выставлен. LiveKit недоступен → `502`.
- **`LiveKit::url` сервера** — только внутренний `ws://host:port`, проверяется при старте.
- **`RoomToken` больше не содержит `url`** (уточнение 0018): адрес голоса — это сам лагерь,
  `wss://<тот адрес, по которому клиент дошёл до API>`. Сервер не может знать, каким
  адресом (LAN/внешний/домен) пользуется клиент; клиент знает. `CampClient::voice_url()`
  отдаёт этот адрес и заодно закрепляет отпечаток лагеря для транспорта.
- **Клиент** при старте регистрирует `PinnedTransport` в `livekit-net` (`WsClient` +
  `HttpClient`): `wss://`/`https://` — только к адресам из реестра отпечатков, через
  `oc-tls`; неизвестный адрес — отказ до любого сетевого обмена. Открытый `ws://` —
  только к loopback и только в debug-сборке (`pnpm livekit` до шага 4); в release — никогда.
- `livekit-net` подключён ровно той версией, что у SDK (`=0.1.4`); в `Cargo.lock` —
  одна копия.

## Проверка
- Сквозной тест (`voice_goes_through_the_camp_server_over_pinned_tls`, CI-задача `voice`):
  сервер в процессе → вход → токен → `wss://` к порту лагеря → настоящий LiveKit.
  Без регистрации транспорта он падает с «TLS support not compiled in» — значит, SDK
  действительно ходит через наш транспорт.
- Тесты прокси без LiveKit (поддельный WebSocket-сервер): путь и query сохраняются,
  `Host` переписан, кадры в обе стороны, чужой отпечаток не пускает, `/twirp` → 404.

## Отвергнуто
- **Отдельный TLS-порт под LiveKit** — второй сертификат/отпечаток или общий ключ на два
  процесса, и LiveKit со всем API торчит наружу.
- **Адрес голоса от сервера (как в 0018)** — неверен для клиента из другой сети.
