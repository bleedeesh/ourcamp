# 0039. Порты на роутере через UPnP, «серый» адрес, проверка

**Дата:** 2026-10-29 · **Статус:** принято · шаг 7 M3, продолжает [0037](0037-friends-address.md) ·
**Код:** `crates/oc-server/src/upnp.rs`, `ports.rs`, `network.rs` (`is_public`, `Router`),
`apps/server/src-tauri/src/address.rs`, `apps/server/src/address.ts`

## Контекст
Чтобы друзья зашли на домашний сервер из интернета, на роутере должны быть открыты порты
7780 и 7881 (TCP), 7882 (UDP), а в ссылке — внешний адрес. Вручную это мало кто сделает.
У многих провайдер даёт «серый» адрес (CGNAT), и тогда снаружи не попасть вовсе. На ПК
Димы роутер ответил по UPnP внешним адресом `100.91.68.10` — это как раз CGNAT.

## Решение
- **Свой UPnP-клиент, без библиотеки** (ADR-0007):
  - поиск роутера SSDP (multicast `239.255.255.250:1900`) с сокета, привязанного к
    основной сети, иначе Windows шлёт его в WSL, Docker или VPN-адаптер;
  - описание устройства → служба `WANIPConnection:2/1` или `WANPPPConnection:1`;
  - SOAP-команды `GetExternalIPAddress`, `AddPortMapping`, `DeletePortMapping`.
  XML читается по именам элементов: общий парсер не нужен.
- **Вариант «Интернет через роутер — внешний IP»** в «Адресе в ссылке». Он появляется,
  если роутер ответил по UPnP.
- **Порты открываются только при этом выборе** и только при «белом» адресе. Сервер не
  трогает роутер без решения хозяина.
  - Аренда — 1 час, продление каждые 30 минут. Роутеры, которые умеют только вечные
    пробросы (ошибка 725), получают вечный.
  - При остановке сервера пробросы снимаются. Если роутер отказал (718 — порт занят
    другим устройством), повтор через минуту, а окно объясняет, какие порты открыть
    вручную.
- **«Серый» адрес** (`network::is_public`: частные сети, `100.64/10`, link-local) помечается
  в списке «· серый». Если его выбрать, окно прямо говорит: из интернета не подключиться,
  нужен Radmin VPN или хостинг. Ссылка остаётся по основной сети, порты не открываются.
- **Проверка изнутри.** После проброса сервер подключается к своему внешнему адресу.
  Ответ — значит, порт открыт. Нет ответа — это **не** доказательство закрытого порта:
  многие роутеры не возвращают подключения к себе (нет NAT loopback). Тогда окно честно
  пишет «попросите друга зайти». Внешнего сервиса проверки нет: он был бы посредником
  (ADR-0035).
- **Headless:** `--host router` — найти роутер, взять внешний адрес и открыть порты. При
  «сером» адресе или без UPnP сервер не стартует и говорит почему.

## Отвергнуто
- **Крейт `igd-next`** — SSDP и три SOAP-вызова занимают ~400 строк, и они в наших руках.
- **NAT-PMP / PCP** — пока нет. UPnP есть у большинства домашних роутеров; добавить
  можно отдельной записью.
- **Открывать порты всегда** — сервер менял бы роутер без спроса.
- **Проверка доступности сторонним сервисом** — посредник и утечка адреса.

## Последствия
- Клиент уже обновляет адрес сервера по новой ссылке: тот же отпечаток при входе заменяет
  запись (`Camps::join`).
- Сменился «белый» IP у провайдера — нужна новая ссылка или DDNS-домен (ADR-0037).
