# 0010. Токены комнаты до M3: клиент подписывает их сам (только debug)

**Дата:** 2026-10-27 · **Статус:** принято, временно (до M3)

## Контекст
Для входа в комнату LiveKit нужен JWT, подписанный ключом сервера. По ADR-0004 токены
выдаёт API лагеря, но сервер лагеря появится только в M3, а голос нужен в M2.

## Решение
- Для разработки — `livekit-server --dev` (ключ `devkey`, секрет `secret`, порт 7880).
- В **debug-сборке** клиент сам подписывает токен этим ключом (`livekit-api`, только
  `access-token`). Адрес сервера и имя участника — из переменных окружения
  `OC_LIVEKIT_URL` (по умолчанию `ws://127.0.0.1:7880`) и `OC_IDENTITY`.
- Код подписи — за `#[cfg(debug_assertions)]`, в release его нет. Release-сборка до M3
  в комнату не входит и говорит об этом в окне.
- Комната = `<campId>/<channelId>`.

## Почему
- Минимум временного кода: одна функция, в M3 заменяется запросом к API лагеря.
- Отдельный dev-сервер токенов — это ещё один процесс для запуска и код, который
  выбросим в M3.

## Последствия
- Ключ `devkey/secret` известен всем и годится только для локального сервера.
- В M3 эта запись заменяется новой: токен выдаёт API лагеря после проверки пользователя.
