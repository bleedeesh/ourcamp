# 0043. Сервер для Linux: архив со статическим бинарником и службой systemd

**Дата:** 2026-10-29 · **Статус:** принято · дополняет [0022](0022-managed-livekit.md), [0041](0041-owner-cli.md), [0042](0042-domain-certificate.md) ·
**Код:** `packaging/linux/`, `dev/pack-server.ts`, `dev/test-server-install.sh`, задача CI `server-linux`

## Контекст
Сервер на хостинге — это Linux без окна. Владелец скачивает архив, запускает установку,
и сервер работает как служба: стартует с машиной, перезапускается после сбоя, пишет в
журнал, переживает обновление.

## Решение
- **`ourcamp-server-<версия>-linux-<x64|arm64>.tar.gz`** с `.sha256` рядом. Внутри:
  - `oc-server`, собранный под **musl** статически: один файл, работает на любом
    дистрибутиве, glibc не важна. Си-части (ring, SQLite) собирает `musl-gcc`;
  - `livekit-server` той же закреплённой версии и с тем же хешем, что у
    `pnpm livekit:fetch`. Сервер находит его рядом с собой;
  - служба systemd, `install.sh`, обёртка `ourcamp`, `server.env`, хук certbot и `README.txt`
    по-русски.
- **Сборка:** `pnpm server:pack` на Linux. Архитектура — своя, потому что livekit-server
  скачивается под неё. CI собирает обе на своих раннерах (`ubuntu-24.04`,
  `ubuntu-24.04-arm`) и выкладывает архивы как артефакты. Публикация в Releases — вместе
  с установщиками M8.
- **`install.sh`** (POSIX sh, от root):
  - создаёт системного пользователя `ourcamp`;
  - кладёт программы в `/opt/ourcamp`, настройки в `/etc/ourcamp/server.env`, данные в
    `/var/lib/ourcamp` (`StateDirectory`);
  - `--host` правит только этот флаг в настройках;
  - повторный запуск — это обновление: настройки и данные остаются, служба
    перезапускается на новых программах.
- **Служба:**
  - `ExecStart=… $OURCAMP_ARGS` из `server.env`: те же флаги, что у `oc-server`, новых
    форматов настроек нет;
  - работает от `ourcamp` в песочнице systemd (`ProtectSystem=strict`, без прав, кроме
    `CAP_NET_BIND_SERVICE` для `--bind :443`), `Restart=on-failure`;
  - `KillMode=mixed`: SIGTERM получает только `oc-server`, а свой LiveKit останавливает
    сам.
- **`oc-server` останавливается чисто и по SIGTERM**, не только по Ctrl+C. Это `systemctl stop` и
  `docker stop`: LiveKit, порты на роутере, файл управления.
- **Команды владельца:** `sudo ourcamp status`. Обёртка запускает
  `oc-server --data /var/lib/ourcamp …` от пользователя `ourcamp` — только у него есть доступ
  к `control.json`. Флаги вместо команды (`ourcamp --bind …`) обёртка не принимает: они
  запустили бы второй сервер рядом со службой.
- **Let's Encrypt:** `/etc/letsencrypt` доступен только root. Хук `--deploy-hook` при каждом
  продлении копирует `fullchain.pem` и `privkey.pem` в `/etc/ourcamp/tls`: группа `ourcamp`,
  `0640`, через временный файл и `mv`. Сервер подхватывает их сам (ADR-0042).
- **Проверка в CI на настоящем systemd раннера** (`dev/test-server-install.sh`):
  - бинарник статический;
  - после установки отвечает `status`, ссылка с нужным адресом, LiveKit запущен;
  - команда владельца работает;
  - обновление сохраняет настройки и лагерь;
  - `systemctl stop` не оставляет ни LiveKit, ни `control.json`.

## Отвергнуто
- **glibc-сборка на старом Ubuntu** — привязка к версии glibc. А статический бинарник —
  это и Alpine, и любой VPS. Медленный аллокатор musl серверу в десятки человек не мешает.
- **Пакеты .deb/.rpm** — по формату и репозиторию на семейство дистрибутивов. Архив с
  `install.sh` одинаков для всех. Пакеты — когда будет кому их ставить через `apt`.
- **Docker-образ первым** — для голоса нужны UDP-порты и `node_ip` хоста. Это проще
  объяснить без контейнера. Образ можно сделать позже поверх того же статического бинарника.
- **`DynamicUser=`** — пользователь существует только пока служба работает, и
  `sudo -u ourcamp` для команд владельца не всегда находит его. Обычный системный
  пользователь проще.
- **Свой файл настроек сервера** — флаги уже описаны в `--help`, и одной строки
  `OURCAMP_ARGS` хватает.
