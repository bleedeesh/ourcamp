# 0052. macOS: линковка с `-ObjC`

**Дата:** 2026-10-31 · **Статус:** принято
**Код:** `.cargo/config.toml`

## Контекст
Тест из ADR-0050 создаёт `PeerConnectionFactory` и стал первым тестом на macOS, который до этого дошёл: тесты
с настоящим LiveKit в CI идут только на Ubuntu. На macOS процесс завершился:

```text
NSInvalidArgumentException: +[NSString stringForStdString:]: unrecognized selector
... RTCDefaultVideoEncoderFactory supportedCodecs ... PeerConnectionFactory::Create
```

Этот метод добавляет к `NSString` Objective-C-категория внутри готового libwebrtc. Линкер берёт объект из статической
библиотеки, только если на него ссылаются по символу, а у методов категорий таких символов нет. Поэтому они не попадают
в программу. Флаг `-ObjC` велит загружать все объекты с Objective-C-кодом.

Настоящий клиент линкует тот же libwebrtc и создаёт ту же фабрику при входе в голосовой канал, поэтому на macOS он,
вероятно, падал бы так же. Это вывод из кода: приложение на macOS я не запускал. Сборка и `pnpm dev` на macOS работали,
потому что сбой наступает только при создании фабрики.

## Решение
Добавить `-C link-arg=-ObjC` для целей macOS в `.cargo/config.toml`, рядом с настройками линковки для Windows.

## Почему
Флаг лежит там же, где статический CRT из ADR-0012, и действует на все программы и тесты рабочего пространства. Запись в
`build.rs` пришлось бы повторять для каждого приложения.

## Отвергнутые варианты
- **Не создавать фабрику в тесте на macOS.** Тест снова стал бы зелёным, а ошибка осталась бы в приложении.
- **`-force_load` для одной библиотеки.** Нужен путь к распакованному libwebrtc, а он зависит от каталога сборки.

## Последствия
- Программы на macOS могут стать немного больше: загружается весь Objective-C-код из статических библиотек.
- Проверка пока только в CI: новый тест на macOS. Вход в голосовой канал в настоящем приложении на macOS никто не проверял,
  это остаётся задачей шага 6 M6 и M8.
