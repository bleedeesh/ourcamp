# 0028. Модерация: выгнать, перенести, запретить говорить

**Дата:** 2026-10-28 · **Статус:** принято · продолжает [0026](0026-camp-roles-and-management.md) ·
**Код:** `crates/oc-server/src/manage.rs`, `rooms.rs`, `api.rs` (`/api/v1/events`),
`apps/desktop/src-tauri/src/voice/room.rs`, `camps.rs`

## Решение
### Три действия (владелец из окна; админы и модераторы из клиента — следующий шаг)
- **Выгнать с сервера** — кик без бана: участник удаляется (как «покинуть сервер»), LiveKit
  выводит его из канала (`RemoveParticipant`), его клиенту приходит адресное событие
  `kicked` — тот выходит из голоса, убирает сервер из списка и говорит «Вас выгнали с
  сервера». Вернуться можно по ссылке для друзей. Бан — позже, отдельно.
- **Перенести в канал** — адресное событие `moved` с каналом: клиент сам переходит туда
  (у LiveKit без облачного `MoveParticipant` сервер не умеет пересаживать сам). Только для
  того, кто сейчас в голосе, и только в голосовой канал.
- **Запретить говорить** — до снятия, переживает переподключения и перезапуск:
  - в базе — флаг участника `silenced` (схема v5), в снимке — `MemberInfo::silenced`;
  - LiveKit не даёт публиковать звук: токен комнаты без `canPublish`, а тому, кто уже в
    канале, сервер меняет права (`UpdateParticipant`) — LiveKit снимает его микрофон сам;
  - клиент без права публикации не публикует микрофон, а когда право вернули — публикует
    его снова (`ParticipantPermissionChanged`); кнопка микрофона заблокирована с подписью.
    LiveKit снимает трек у себя, но Rust SDK (0.9.7) оставляет локальную публикацию — при
    запрете клиент сам снимает её (`unpublish_track`, сам трек и микрофон продолжают
    работать), иначе после снятия запрета публиковать было бы «нечего». Проверено тестом
    с настоящим LiveKit (`voice/room.rs`).
  Защита — на LiveKit, не на честности клиента.
- В окне сервера у каждого участника: запретить/разрешить говорить, выгнать (с
  подтверждением). Перенос — перетаскиванием на канал, см. [0029](0029-drag-to-move.md). Запрещённый виден у всех
  значком микрофона на красной подложке — отличается от «выключил сам».

### Адресные события
`/api/v1/events` (ADR-0021) кроме общего снимка несёт события одному участнику
(`CampEvent::Moved`, `CampEvent::Kicked`): сервер знает, чья это сессия, и шлёт только ему.
После `kicked` поток закрывается.

## Отвергнуто
- **Запрет только в интерфейсе клиента** — изменённый клиент его обойдёт.
- **Отдельный канал для команд** — тот же WebSocket уже есть и авторизован.
