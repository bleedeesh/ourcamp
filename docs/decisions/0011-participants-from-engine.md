# 0011. Состав костра приходит из движка

**Дата:** 2026-10-27 · **Статус:** принято

## Контекст
В M0 список участников костра брался из `demo-camp.ts` и передавался в
`joinChannel`. С настоящей комнатой LiveKit истина о том, кто сидит в костре и
выключил ли он микрофон, — у комнаты, а люди входят и выходят в любой момент.

## Решение
- Контракт `VoiceEngine` **расширяется, существующие методы не меняются**: добавляется
  подписка `onParticipants` — событие `voice://participants` с полным списком удалённых
  участников (`userId`, `micMuted`) при каждом изменении.
- `joinChannel.members` остаётся: по нему движок заранее знает сохранённые громкости
  и mute. Участник, пришедший позже, получает громкость из того же `VolumeBook` —
  `VoiceController` вызывает `setVolume`/`setLocalMute`, когда видит нового человека.
- Дерево костра, в котором сидит пользователь, показывает людей из комнаты; остальные
  костры до M3 остаются демо.
- Событие несёт полный список, а не «вошёл/вышел»: пропущенное событие не оставляет
  UI в рассинхроне.

## Почему
Одна точка правды (принцип 4 в `architecture.md`): UI не угадывает состав комнаты.

## Отвергнуто
- **Демо-список + `OC_IDENTITY`** без событий: звук только от «известных» участников,
  кто вошёл не по сценарию — не слышен и не виден. Костыль до M3.

## Последствия
- В M3 присутствие во всех кострах придёт с сервера лагеря (вебхуки LiveKit, ADR-0004);
  `onParticipants` остаётся источником для костра, где пользователь сам.
- `DemoEngine` тоже реализует `onParticipants` (отдаёт демо-состав).
