# 0004. LiveKit как SFU внутри OurCamp Server

**Дата:** 2026-10-27 · **Статус:** принято

## Контекст
При 3+ участниках нужен SFU (сервер пересылает потоки, а не каждый шлёт каждому).

## Решение
OurCamp Server запускает и контролирует **livekit-server** (Go, Apache 2.0) как дочерний
процесс; один костёр = одна комната LiveKit. Клиент — **LiveKit Rust SDK**.
Токены доступа к комнате выдаёт API лагеря после проверки пользователя.

## Почему
- Единственный SFU с поддерживаемым Rust-клиентом (на libwebrtc).
- Из коробки: simulcast/SVC, адаптивный поток, RED для аудио, встроенный TURN.
- Модель «комната / участник / дорожка» один-в-один ложится на «костёр / человек / голос, стрим».

## Отвергнуто
- **mediasoup** — меньше CPU на участника, но сигнализацию и клиентскую логику писать
  самим, Rust-клиента нет. Для масштаба лагеря (десятки человек) разница в CPU не важна.
- **Janus** — силён в SIP/вещании, которые не нужны.
- **P2P mesh** — разваливается на 4–5 участниках.

## Последствия
- Установщик сервера включает бинарник livekit-server под каждую ОС.
- Присутствие «кто в каком костре» сервер лагеря берёт из вебхуков LiveKit и рассылает
  клиентам — дерево видно без подключения к каналу.
