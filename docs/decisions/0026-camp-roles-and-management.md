# 0026. Роли и управление лагерем

**Дата:** 2026-10-28 · **Статус:** принято · заменяет ключ админа из [0005](0005-invite-links.md) и
[0018](0018-camp-login-protocol.md) (ссылка «для вас») · **Код:** `crates/oc-server/src/store.rs`
(v4), `crates/oc-server/src/manage.rs`, `apps/server`

## Контекст
Пока не было окна сервера, админом становился тот, кто первым погасил одноразовый ключ.
С окном у лагеря есть хозяин, который сидит за этим компьютером, — ему и решать, кто
админ. Ещё нужно: переименовать лагерь, править каналы (в том числе удалять костёр, где
сидят люди), модерировать.

## Решение
### Роли
| Роль | Кто | Может |
|---|---|---|
| **владелец** | тот, кто запустил сервер (окно / headless) | всё; не участник лагеря, действует только из окна |
| **админ** | назначает владелец | название лагеря, каналы, назначать и снимать модераторов + всё модераторское |
| **модератор** | назначает владелец или админ | кик из лагеря, перенос в другой костёр, выключить микрофон у всех |
| **участник** | вошёл по ссылке для друзей | — |

- Права проверяет **одно место** в ядре (`manage.rs`: действие + кто его делает). Окно
  вызывает его как владелец; админы и модераторы из клиента — через API, тот же код.
- Назначать и снимать админов может только владелец: админ не может «захватить» лагерь,
  сняв других админов.
- **Ключ админа и ссылка «для вас» уходят.** Миграция v4 удаляет непогашенные ключи;
  старая ссылка-ключ при проверке — «больше не действует». Кто уже админ — остаётся.

### Каналы
- У канала есть тип: **голосовой** (костёр) или **текстовый** (чат, M5). Клиент пока
  рисует только костры; текстовые видны и правятся в окне сервера.
- Новый лагерь: **Voice** (голос), **Chat** (текст), **AFK** (системный, ADR-0025).
  Создаются после миграций только в новой базе — миграции переносят старые данные, а не
  решают, с чего начинается новый лагерь. Существующие лагеря свои каналы сохраняют.
- AFK переименовать можно, удалить — нет. Удаление голосового канала с людьми: сервер
  закрывает комнату в LiveKit (`DeleteRoom`), клиенты получают разрыв с причиной «костёр
  удалён» и выходят из него.

### Живое состояние
- Снимок `CampState` (ADR-0021) несёт и **сам лагерь**: название и каналы. Переименование,
  новый или удалённый канал доходят до клиентов без перезахода — тем же потоком
  `/api/v1/events`; после действия сервер публикует снимок сразу, не ждёт опроса LiveKit.
- У участника в снимке — **роль** (`member` / `moderator` / `admin`), а не флаг «админ».

## Отвергнуто
- **Сохранить ключ админа рядом с окном** — два способа стать админом, и первый (кто
  быстрее откроет ссылку) хуже второго.
- **Владелец как участник с ролью `owner`** — у хозяина может не быть клиента на этом
  компьютере, а участник лагеря с правами владельца уязвим к утечке ключа устройства.

## Последствия
- Действия админов и модераторов из клиента (меню участника, настройки лагеря) — следующий
  шаг после окна; API для них — по тем же правам.
- Кик удаляет участника (как «покинуть лагерь», но с причиной) и выводит его из голоса.
- У headless-сервера (`oc-server`, без окна) владельцу действовать пока нечем: назначать роли
  и править лагерь там будут подкоманды CLI (следующие шаги), до тех пор — только окно.
