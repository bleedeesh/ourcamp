# 0009. Обработка микрофона в M2 — APM из libwebrtc

**Дата:** 2026-10-27 · **Статус:** принято · частично заменяет [0008](0008-audio-quality-defaults.md)
(шумодав до M7)

## Контекст
ADR-0008 задаёт цепочку AEC3 → шумодав (DeepFilterNet/RNNoise) → AGC. В libwebrtc, который
приходит с LiveKit Rust SDK, уже есть `AudioProcessingModule` (APM): AEC3, свой шумодав,
AGC и фильтр низких частот — одним модулем, кадрами по 10 мс (i16).

Звук выводит наш микшер через cpal, а не libwebrtc, поэтому сам SDK не знает, что
играет в наушниках, и эхо не подавит: опорный сигнал нужно передать вручную.

## Решение
- В M2 микрофон обрабатывает **один экземпляр APM**: эхо + шумодав WebRTC + AGC + HPF.
  Внешний шумодав не подключаем.
- **Опорный сигнал для AEC3** — копия выхода `MixerCore` (после лимитера, то есть
  ровно то, что уходит на устройство). Аудиопоток вывода только кладёт её в lock-free
  кольцо; в APM (`process_reverse_stream`) её подаёт поток обработки микрофона, перед
  каждым кадром захвата. Аудиопоток вывода APM не вызывает: внутри APM есть блокировки.
- Задержку `set_stream_delay_ms` берём из буферов cpal (вывод + захват); точную
  подстройку делает встроенный в AEC3 оценщик задержки.
- RNNoise («лёгкий») и DeepFilterNet («качественный») появятся в M7 вместе с выбором
  в настройках. Тогда APM разделится на два прохода (AEC → внешний шумодав → AGC),
  шумодав WebRTC при этом выключается — шумодав в цепочке всегда один.

## Почему
- Ноль новых зависимостей: APM уже внутри libwebrtc.
- Цепочка AEC3 → NS → AGC внутри APM идёт в правильном порядке и отлажена на
  миллиардах звонков. Встраивать внешний шумодав между AEC и AGC имеет смысл, когда
  есть настройки, чтобы сравнить на слух (M7).

## Отвергнуто
- **RNNoise сразу (nnnoiseless).** Два прохода APM и ещё 10 мс задержки уже в M2, когда
  главное — довести голос до собеседника.
- **`AudioSourceOptions { echo_cancellation: true, … }` у `NativeAudioSource`.** Без
  звукового устройства libwebrtc у этого AEC нет опорного сигнала, и эхо он не убирает.

## Последствия
- У `MixerCore` появляется отвод выхода (tap) — ещё одно SPSC-кольцо, в аудиопотоке
  без блокировок и аллокаций (правила ADR-0006 не меняются).
- При смене устройства вывода (M7) кольцо опорного сигнала пересоздаётся вместе с микшером.
