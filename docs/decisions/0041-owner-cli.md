# 0041. Команды владельца для headless-сервера

**Дата:** 2026-10-29 · **Статус:** принято · дополняет [0026](0026-camp-roles-and-management.md), [0028](0028-moderation.md) ·
**Код:** `crates/oc-server/src/control.rs`, `crates/oc-server/src/owner.rs`

## Контекст
На хостинге окна сервера нет: `oc-server` запущен как служба. Владельцу всё равно нужно
давать роли, менять каналы, выгонять, открывать сервер. Раньше это умело только окно.

## Решение
- **Команды — тем же бинарником:** `oc-server [--data DIR] <команда>`. Первое слово без
  `-` — команда владельца; иначе сервер запускается как раньше.
  - `status`, `role`, `rename`, `channel add|rename|remove`, `kick`, `silence`,
    `unsilence`, `move`, `open`, `invite-only`. Полный список — `--help`.
  - Кого и какой канал — по имени (без учёта регистра) или по id из `status`. Если имя
    у нескольких, ответ перечисляет их id.
  - Имя из нескольких слов не нужно брать в кавычки: `rename Вечерний кооп`.
- **Команда идёт в работающий сервер, а не в базу.** Запущенный лагерь слушает
  `127.0.0.1` на случайном порту и пишет `control.json` (порт + ключ 32 байта) в папку
  данных. Команда читает файл и делает запрос с этим ключом.
  - Всё проходит через `Manager` — тот же код, что у окна. Участники видят изменения
    сразу (адресные события, права LiveKit), без перезапуска.
  - Команда отвечает, когда снимок лагеря уже содержит изменение (`Manager::settled`,
    счётчик изменений в `presence::Refresh`). Поэтому `channel add Катка` и следом
    `move Лена Катка` в одном скрипте находят новый канал, а `status` показывает новое.
    Ждём не дольше 5 с: изменение сохранено в любом случае.
  - Право = доступ к папке данных. Там уже лежат ключ сертификата и база, поэтому новой
    границы доверия нет. На unix файл — `0600`.
  - Ключ сравнивается за постоянное время. При остановке файл удаляется.
- **Окно сервера тоже открывает управление**: командами можно управлять и им, если
  указать его папку данных.
- Ответы — по-русски, как в окне. Ошибки идут в stderr с кодом выхода 1; неверные
  аргументы — с кодом 2.

## Отвергнуто
- **Писать прямо в SQLite** — тогда сервер не узнает о переменах. Выгнанный остался бы
  в голосе, а запрет говорить не дошёл бы до LiveKit.
- **HTTPS API лагеря с подписью ключом владельца** — пришлось бы держать ключ владельца на
  сервере или носить его с собой. Сейчас владелец — это тот, кто управляет машиной.
- **Сокет unix / именованный канал Windows** — два кода вместо одного. Loopback с ключом в
  файле работает одинаково везде.
- **Интерактивная консоль в запущенном сервере** — у службы (systemd) нет терминала.
