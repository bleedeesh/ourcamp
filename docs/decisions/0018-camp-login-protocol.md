# 0018. Вход в лагерь и токены комнат

**Дата:** 2026-10-27 · **Статус:** принято · уточняет [0015](0015-device-identity.md) ·
**Код:** `crates/oc-server`, `crates/oc-camp-client`

## Протокол
Все запросы — по TLS с пиннингом (ADR-0014), JSON.

```text
POST /api/v1/auth/challenge                      → { nonce }               (32 байта, base64url, 60 с, одноразовый)
POST /api/v1/auth/login  { publicKey, name, nonce, signature, invite? }
                                                 → { session, userId, role }
POST /api/v1/channels/{id}/token   Authorization: Bearer <session>
                                                 → { url, token }          (JWT LiveKit)
```

- **Подписывается** `"ourcamp-login-v1\n" + <fp лагеря> + "\n" + nonce` ключом Ed25519
  устройства. **Отпечаток сертификата, а не хост** (уточнение 0015): он однозначно
  задаёт лагерь и не зависит от адреса (LAN/интернет/домен), а чужой лагерь, получив
  подпись, не сможет войти с ней в этот — у него другой отпечаток. Префикс с версией
  не даёт перепутать подпись входа с любой будущей подписью.
- **`userId`** = Crockford base32 первых 10 байт SHA-256 открытого ключа (16 символов).
- **Первый вход требует приглашение** (`join` или `claim`); дальше ключ узнаётся сам.
  Ключ админа (`claim`) гасится в той же транзакции, что создаёт или повышает участника —
  двое одновременно админами не станут. Уже вошедший участник может погасить `claim`.
- **Сессия** — 32 случайных байта, в базе хранится только SHA-256 (в отличие от
  приглашений, показывать её снова не нужно), живёт 30 дней.
- **Токен комнаты**: identity = `userId`, name = имя участника, комната = id канала
  (один LiveKit на лагерь), права — войти, говорить, слушать; TTL 1 час (на
  переподключениях LiveKit сам выдаёт обновлённый токен). `url` в M3 шаг 2 — адрес
  LiveKit из конфигурации сервера; в шаге 3 — прокси `/rtc` на том же TLS-порту.
- **Ошибки** — стабильные коды: `bad_request`, `invite_required`, `invite_invalid`, `claim_used`,
  `bad_signature`, `nonce_invalid`, `unauthorized`, `not_found`.

## Реализация
- Ed25519 — из `ring` (уже в дереве ради TLS) вместо `ed25519-dalek`, названного в 0015.
- Клиентская сторона — крейт `oc-camp-client` (без Tauri): ключ устройства, HTTPS через
  `hyper` поверх `oc-tls`, вызовы API. Им же пользуются сквозные тесты сервера.
- Подключение приложения (вместо dev-токенов ADR-0010) — в шаге 4, вместе с каналами
  с сервера в UI: до этого UI показывает демо-каналы, которых нет на сервере.

## Отвергнуто
- **Подпись хоста** (0015) — ломается, когда лагерь доступен по нескольким адресам.
- **Пароли/коды вместо ключа** — их можно подсмотреть и переиспользовать; ключ не
  покидает устройство.
- **JWT как сессия** — отзыв требует списка отозванных; случайный токен с хешем в базе
  проще и отзывается удалением строки.
