# 0013. Локальный LiveKit для разработки — в Docker

**Дата:** 2026-10-27 · **Статус:** принято · **Код:** `dev/compose.yaml`

## Контекст
Для M2 нужен `livekit-server --dev`. Скачивать бинарник вручную и держать его на
компьютере разработчика не хочется. Docker у разработчика есть или ставится один раз.

## Решение
- `dev/compose.yaml` поднимает только SFU (`livekit/livekit-server`, версия закреплена);
  запуск — `pnpm livekit`, остановка — `pnpm livekit:down`.
- Клиент в контейнер **не** уходит: ему нужны настоящие микрофон, колонки и окно, а
  сборке — MSVC и WebView2 на хосте.
- Порты: 7880 (сигнализация), 7881/tcp и 7882/udp (WebRTC; в `--dev` все участники
  мультиплексируются на один UDP-порт, поэтому диапазон портов не нужен).
- `--node-ip 127.0.0.1` по умолчанию, `OC_NODE_IP=<IP компьютера>` — для второго ПК в сети.

## Почему `--node-ip`
Сервер в контейнере видит только свой адрес во внутренней сети Docker и кладёт его в
ICE-кандидаты. С хоста этот адрес недоступен — сигнализация подключится, а звук не пойдёт.
`--node-ip` задаёт адрес, по которому клиент действительно достучится до опубликованных портов.

## Отвергнуто
- **`network_mode: host`** — в Docker Desktop под Windows работает не во всех версиях
  и требует отдельной настройки; с явными портами поведение одинаково на всех ОС.
- **Бинарник в репозитории** — 50+ МБ на каждую ОС, обновлять руками.

## Последствия
- В M3 livekit-server запускает сам OurCamp Server (ADR-0004); compose остаётся для
  разработки клиента без сервера лагеря.
