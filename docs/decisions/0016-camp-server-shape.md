# 0016. Устройство OurCamp Server

**Дата:** 2026-10-27 · **Статус:** принято (реализация — M3) · дополняет 0003, 0004

## Решение
- **Ядро — крейт `crates/oc-server`** (axum + SQLite, без UI). Два входа:
  - окно Tauri `apps/server` в стиле клиента: статус, ссылки «для вас» (ключ админа)
    и «для друзей», кто в лагере; сворачивается в трей. Делается в конце M3;
  - `--headless` — тот же сервер без окна (VPS, Docker, CI), ссылки — в лог.
- **Один порт для клиента — 7780/TCP (TLS).** Сервер отдаёт API лагеря и
  проксирует WebSocket сигнализации LiveKit (`/rtc`); сам LiveKit слушает только
  `127.0.0.1`. Наружу: 7780/tcp, медиа 7881/tcp и 7882/udp. Один сертификат, один
  отпечаток в ссылке (ADR-0005, 0014).
- **Сертификат** самоподписанный, генерируется при первом запуске (`rcgen`) и
  хранится рядом с базой: отпечаток в разосланных ссылках не меняется между
  перезапусками.
- **LiveKit — два режима:**
  - `managed` (по умолчанию в сборке для людей): бинарник из установщика, дочерний
    процесс под присмотром (перезапуск при падении, остановка вместе с сервером),
    ключ API генерируется при первом запуске;
  - `external` (разработка): `--livekit-url ws://127.0.0.1:7880` к `pnpm livekit`
    из Docker (ADR-0013) — разработчику ничего не нужно скачивать.
- **Токены комнат** выдаёт API лагеря после входа (ADR-0015) — заменяет dev-токены
  ADR-0010. Права в токене: только свой костёр.
- **Присутствие** — вебхуки LiveKit → сервер → всем клиентам лагеря по WebSocket API:
  дерево всех костров видно без подключения к голосу (ADR-0004).

## Почему один порт
Хозяину проще пробросить и объяснить друзьям один TCP-порт для всего, кроме медиа;
LiveKit не торчит наружу со своим API-ключом.

## Последствия
- В M3 клиент получает каналы и людей с сервера; `demo-camp.ts` остаётся только
  для `DemoEngine` в браузере.
- UPnP/NAT-PMP — отдельный шаг в конце M3.
