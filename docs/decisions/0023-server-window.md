# 0023. Окно сервера лагеря (Tauri)

**Дата:** 2026-10-28 · **Статус:** принято (реализация — M3, шаг 6) · уточняет [0016](0016-camp-server-shape.md) ·
**Код:** `apps/server`, `crates/oc-server` (`Running::camp_state`, `Running::livekit_pid_changes`)

## Контекст
Хозяин лагеря — не админ серверов: ему нужно окно, где видно, что лагерь работает, какие
ссылки разослать и кто пришёл. Ядро уже есть (`oc-server::start`, ADR-0016); headless-режим
(`oc-server`, лог в терминал) остаётся для VPS и CI.

## Решение
- **Отдельное приложение `apps/server`** («OurCamp Server», `app.ourcamp.server`): Tauri 2 +
  React, тот же стек и та же тема, что у клиента. Ядро — `oc-server` как библиотека, в том
  же процессе; LiveKit — `managed` (ADR-0022), бинарник рядом с exe, в debug — `dev/bin`.
- **Общий UI** (токены темы, `base.css`, логотип-костёр, заголовок окна) — пакет
  `packages/ui` в pnpm-воркспейсе, его импортируют оба приложения. Не копия и не импорт
  «через соседнее приложение».
- **Окно 420×640**, без системной рамки, как клиент. Содержимое сверху вниз:
  - статус: «Лагерь работает» / «Запускается…» / ошибка старта целиком (занятые порты,
    нет livekit-server) и «Попробовать снова»;
  - две ссылки с кнопкой «Скопировать»: «для друзей» и «для вас (админ)» — вторая видна,
    пока в лагере нет админа (погашенный ключ = появился админ);
  - кто в лагере: имя, корона, в каком костре сидит (тот же снимок `CampState`, что идёт
    клиентам по `/api/v1/events`, — `Running::camp_state()`);
  - внизу мелко: адрес и порт, отпечаток, состояние голоса (LiveKit pid, перезапуски).
- **Данные лагеря** — в папке данных приложения ОС; одна копия на папку (`instance.lock`,
  как у клиента).
- **Трей:** крестик прячет окно в трей — лагерь продолжает работать, друзья не вылетают.
  Меню трея: «Открыть», «Скопировать ссылку для друзей», «Остановить лагерь и выйти»
  (останавливает API и LiveKit по порядку, ADR-0022).
- **Rust → UI:** одно событие `server://status` с полным снимком (статус, ссылки, участники,
  голос) при каждом изменении + команда `server_status` для первого рисования. Пропуск
  события ничего не ломает — следующий снимок полный (как ADR-0021).

## Отвергнуто
- **Окно в клиенте («режим хозяина»)** — сервер должен жить, когда клиент закрыт, и на
  машине, где клиента нет.
- **Окно отдельным процессом над headless `oc-server`** (читать его лог) — хрупкий разбор
  текста; библиотека в процессе даёт типизированное состояние.

## Последствия
- Переименование лагеря, кик/бан, роли — не в M3 (позже, вместе с accounts, M4+).
- Автозапуск с системой и установщик — M8.
