# 0003. Лагеря у пользователей, аккаунты — в общем сервисе

**Дата:** 2026-10-27 · **Статус:** принято

## Контекст
Пользователь, создающий лагерь, скачивает и запускает **OurCamp Server** у себя
(модель TeamSpeak). При этом в клиенте есть регистрация, друзья, личные сообщения
и список «мои лагеря».

## Решение
- **OurCamp Server** (у хозяина): голос/стримы (LiveKit), каналы, чаты лагеря, файлы,
  роли. Хранит данные в SQLite рядом с собой.
- **Accounts service** (один общий, небольшой): регистрация/вход, профили, друзья,
  заявки, личные сообщения, статусы, список лагерей пользователя.
- Сервер лагеря проверяет пользователя по подписанному токену accounts-сервиса
  (JWT, публичный ключ сервиса), сам паролей не хранит.

## Почему
- Голос и переписка лагеря не идут через наши серверы — нагрузка и хранение у хозяина.
- Друзья и личка работают, даже если ни один лагерь не запущен.

## Отвергнуто
- **Полностью без центра** (личность = локальный ключ, как в TeamSpeak): нет друзей вне
  лагерей, нет восстановления аккаунта, экраны входа/друзей теряют смысл.
- **Всё централизованно**: противоречит идее «лагерь у себя».

## Последствия
- Лагерь доступен, только пока компьютер хозяина включён — это показывается в UI
  («Сервер выключен»).
- Нужна работа с NAT: UPnP/NAT-PMP, инструкция для ручного проброса, позже —
  ретранслятор для CGNAT.
