# 0017. Из чего собран OurCamp Server (M3, шаг 1)

**Дата:** 2026-10-27 · **Статус:** принято · **Код:** `crates/oc-server`, `crates/oc-tls`

## Решение
- **TLS — `rustls` с бэкендом `ring`**, не `aws-lc-rs` по умолчанию. `ring` уже в дереве
  (LiveKit, Tauri); `aws-lc-rs` на Windows требует cmake и NASM — лишняя установка у
  разработчика и в CI.
- **Проверка по отпечатку — в отдельном крейте `oc-tls`** (ADR-0014). Его используют
  тесты сервера (запросы к настоящему серверу идут через тот же верификатор) и клиент
  (шаг 3) — один код доверия на обе стороны.
- **SQLite — `rusqlite` с `bundled`**: SQLite компилируется в бинарник, хозяину лагеря
  ничего не нужно ставить. Схема версионируется `PRAGMA user_version`; запросы идут
  через `spawn_blocking`, чтобы диск не тормозил остальные соединения.
- **HTTP — `axum` 0.8 поверх `hyper` 1**, но **цикл приёма TLS свой** (`serve.rs`,
  ~50 строк вместо `axum-server`): таймаут рукопожатия, upgrade для WebSocket-прокси
  (шаг 3), без ещё одной зависимости (ADR-0007).
- **Токены приглашений хранятся в базе как есть**, а не хешами: сервер должен уметь
  показать ссылку «для друзей» и неиспользованный ключ админа после перезапуска (окно
  сервера, шаг 6). База лежит у хозяина рядом с ключом TLS — тот, кто может её прочитать,
  может и подменить сервер целиком.
- **Сертификат пишется атомарно** (временный файл + rename, ключ раньше сертификата), а
  если на диске осталась только половина — сервер **отказывается стартовать**, а не
  генерирует новый: новый отпечаток молча сломал бы все разосланные ссылки.
- **Аргументы командной строки разбираются вручную** (7 флагов) — `clap` ради этого не тянем.

## Последствия
- Резервная копия лагеря = папка `--data` целиком (`camp.db` + `tls/`).
- API версионируется (`apiVersion` в ответе `/api/v1/camp`); клиент будет отказываться
  от серверов, которых не понимает.
