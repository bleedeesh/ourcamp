# 0007. Фронтенд без стейт-менеджера и тест-фреймворка

**Дата:** 2026-10-27 · **Статус:** принято

## Решение
- Состояние — свой `createStore` (≈40 строк) + `useSyncExternalStore`. Логика — в
  классах-контроллерах (`VoiceController`), компоненты только читают срезы и вызывают методы.
- Тесты логики — встроенный `node --test` (Node ≥ 22.18 запускает `.ts` напрямую,
  удаляя типы). Поэтому в коде только «стираемый» TS (`erasableSyntaxOnly`: без enum,
  namespace, parameter properties) и импорты с расширением `.ts`.
- Стили — CSS-переменные (`styles/tokens.css`) и обычный CSS, без CSS-in-JS.
- Иконки — свои инлайн-SVG (~15 штук, в толщину линий логотипа).

## Почему
Каждая зависимость — обновления, размер и чужой API. Здесь их задачи решаются
десятками строк своего кода, который проще читать через год.

## Когда пересмотреть
- Тестам компонентов (рендер, клики) понадобится DOM → добавить vitest + happy-dom.
- Состояние станет сложным (много окон, синхронизация между ними) → пересмотреть стор.
